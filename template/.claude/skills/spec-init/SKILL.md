# spec-init — テンプレートからのプロジェクト立ち上げ

あなたはこれから、仕様駆動開発テンプレートから作られた新しいリポジトリを立ち上げる。ゴールは次の3つ。

1. リポジトリ内の `TODO(spec-init)` プレースホルダがすべて埋まっている（または該当ファイルごと削除されている）
2. `docs/要求定義書.md` に初版（F-XXX が1件以上・優先度付き）ができている
3. 「決めない決定」が決定ログに記録されている

編集は必ず Edit / Write ツールで行い、一括置換スクリプトは使わない。

## 手順0: 適用判断（最初に必ず行う）

README「成立条件と縮退運転」「適用判断」を読み、オーナーに確認する:

- **コード開始前に要求定義書・要件定義書を書き切る期間（目安2〜3日）を取れるか？** 書こうとしても書けないなら、要求の不確実性が高いシグナル。このスキルを中断し、探索フェーズ（仕様書を書かない使い捨てプロトタイプ）を先に行うことを提案する
- 成立条件4つ（意思決定者1人・即日ドッグフーディング・デプロイ摩擦ゼロ・docs がコンテキストに収まる規模）のうち欠けるものがあれば、README の縮退運転を該当箇所に採り入れる前提で進める

## 手順1: 聞き取り

AskUserQuestion で次を確認する（一度に全部聞かず、2〜3問ずつ）:

1. **プロダクト**: 名前・一言の目的・対象ユーザー（シングルユーザーか）
2. **形態**: UI の有無（Web/CLI/API）・DB の有無・デプロイ先・push とリリースの関係（push ≒ 本番か）
3. **技術スタック**: フレームワーク・言語・DB・認証
4. **公開範囲**: リポジトリは public か private か
5. **設計原則の種**: このプロダクトで一貫させたい方針があるか（データの持ち方・削除方針・更新の即応性など。無ければ実装しながら決めてよい）

## 手順2: 構成の刈り込み

聞き取り結果に基づき、使わない文書を**削除**する（空のまま残さない。参照は `docs/README.md` の表からも消す）:

- DB を使わない → `docs/データモデル定義書.md` を削除
- UI が無い → `docs/画面定義書/` を削除（要件定義書 §4 は API/CLI 一覧に読み替える）
- README（プロセス憲章）は `docs/プロセス憲章.md` へ移し、リポジトリ直下の README.md はプロダクトの説明に書き換える

## 手順3: プレースホルダの充足

`TODO(spec-init)` を Grep で全件列挙し、聞き取り結果で1つずつ埋める。対象は主に:

- `CLAUDE.md` — プロジェクト概要・技術スタック・アーキテクチャ要約・設計原則・完了フローの push 条件・開発コマンド・公開範囲・環境変数・固有規約
- `docs/*.md` — 各文書ヘッダのプロダクト名・作成日
- `.claude/agents/verifier.md` — 検証コマンド列
- `.claude/agents/spec-reviewer.md` / `test-reviewer.md` — 設計原則・固有境界値のチェックリスト（CLAUDE.md の設計原則と同期させる）
- `.claude/settings.json` — 頻用する安全なコマンド（テスト・lint 等）を allow に、破壊的・本番系を ask に追加

まだ決められない項目は、placeholder のまま残さず「**未定（YYYY-MM-DD 時点。○○が決まったら記入）**」と書き換え、該当文書の決定ログに保留として記録する。

## 手順4: 要求定義書の初版

オーナーと対話しながら `docs/要求定義書.md` を上から埋める。順序は 背景 → 目的・成功基準 → 対象ユーザー → 前提知識 → 重視する価値 → 機能要求 → 非機能要求 → スコープ外。

- 機能要求は領域ごとに F-1XX / F-2XX と百の位を分けて採番し、MoSCoW で優先度を付ける
- **スコープ外（§8）を必ず埋める**。「やらないこと」「今は決めないこと」を理由付きで挙げ、`log_要求定義書.md` を作成して日付付きで記録する（不変条件5）
- 執筆ガイドの引用ブロック（`>` で始まる説明）は、埋めた節から削除する

## 手順5: 完了確認

1. `TODO(spec-init)` の Grep 結果が 0 件であること
2. 要求定義書に Must の F-XXX が1件以上あること
3. オーナーに次のステップを提示する: 「要件定義書を書き切ってから実装を開始する。以後の流れは CLAUDE.md（docs 先行・サブエージェント運用・完了フロー）に従う」

完了したらこのスキル（`.claude/skills/spec-init/`）は削除してよい（立ち上げ専用のため）。
