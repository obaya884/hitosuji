未実装要求を**決定状態（レーン）＋熟度タグ＋着手トリガ**で管理する。挙動レベルの仕様判断が発生したら**先に**要件定義書群へ反映し、本書はチェックと一行の要約に留める。判断の経緯は各定義書の決定ログ、実装の変遷は git が正。

- **熟度タグ**: `[仕様済]`＝仕様が固まっている／`[設計済]`＝検討ドキュメントあり／`[未詰め]`＝着手時に詳細化。決定状態とは直交する軸
- **見送りの出口**: 候補を見極めた結果やらないと決めたら、要求定義書のスコープ外＋決定ログへ落とす
- **完了の出口**: 実装が完了したエントリは、状態更新と同じコミットで `closed_22_要件バックログ.md` へ移す（最初の1件が出た時点で作成）

> 運用モードの目安: **初期構築（MVP）中は「確定・着手待ち」1レーンを実装順に並べるだけでよい**（リリースまでは全件やると決まっているため、レーン分けは情報を増やさない）。実運用が始まり「やるかどうかを運用で見極める」案件が現れたら3レーン運用に移行する。フェーズ（リリース波）による管理を使った場合は、MVP 完了時にその計画文書を `archive_` 化してこの台帳へ引き継ぐ。
