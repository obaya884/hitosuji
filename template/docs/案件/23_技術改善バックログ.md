## この文書の守備範囲

プロダクトの**挙動**に関わる変更は扱わない（それは要求 → 要件 → 詳細層の軸で、着手前に該当文書を先に直す）。ここに書くのは、ユーザーから見た挙動を変えずに**開発の健全性を上げる活動**——依存追随・CI/ツール整備・内部設計の改善・テスト補強・調査など。挙動が絡むか迷ったら要求軸に振る。

- 採番は **T-XX**（Technical）。1系列で通し、種別で区別する
- 種別: `負債返済` / `改善` / `ツール整備` / `調査`
- 優先度: `高` / `中` / `様子見`
- 状態: `未着手` / `進行中` / `完了` / `保留`
- **完了になったエントリは、状態更新と同じコミットで `closed_23_技術改善バックログ.md` へ移す**（本書には未着手・進行中・保留だけを残す。closed_ ファイルは最初の1件が出た時点で作成）
- 判断の経緯は本文に書かず、`log_23_技術改善バックログ.md` へ日付順に積む（最初のエントリが出た時点で作成）
- リファクタ観点の棚卸しは `refactor-scout`（読み取り専用サブエージェント）が T-XX 案のドラフトを起票し、オーナー確認のうえメインセッションが本書へ記入する
