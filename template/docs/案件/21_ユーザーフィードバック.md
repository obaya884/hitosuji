## 運用ルール

1. 気づきはまず本書に**起票**する（粒度はバラバラで良い。会話で出たものは AI が転記する）
2. 起票時に**分類**する: `不具合` / `改善（軽微）` / `改善（要仕様整理）` / `要求（優先度変更含む）` / `開発環境`
   - この分類軸は機能ではなく**仕様判断の要否**。「軽微」は AI が自走でき、「要仕様整理」だけがオーナーとの対話に乗る
3. 対応するときは通常の開発ルールに従う — **挙動レベルの変更は該当仕様書を先に更新**し（guide_21 の着手手順）、本書には対応結果と参照先だけを残す
4. 状態は `未対応` / `対応中` / `対応済み` / `見送り` の4つ。対応済み・見送りには日付と理由（または反映先）を書く
5. **対応済み・見送りのエントリは、状態更新と同じコミットで `closed_21_ユーザーフィードバック.md` へ原文のまま移す**（本書には未対応・対応中だけを残し、日常的に読むファイルを小さく保つ。closed_ ファイルは最初の1件が出た時点で作成）
