## 1. 基本方針

> 3〜5行で。特に**過剰抽象の禁止**（利用者・開発者の規模に見合わない層や DTO 変換を作らない）はどの規模でも書いておく価値がある。レビューエージェントがこの節を判断基準に使う。

## 2. レイヤー構成

> ディレクトリツリーと各層の責務。「この層に置いてよいもの・いけないもの」を明確に（例: domain は I/O・現在時刻取得禁止、すべて引数で受け取る）。

### ファイル命名規約

> 許される依存の向きを1行の図で（例: domain ← usecases ← { infrastructure, presentation }）。

## 4. 実装スタイルの規約
