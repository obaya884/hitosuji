## 1. 画面の役割

1日を終えたあとの振り返りを行う。S-01 が「これから」と「いま」の画面であるのに対し、本画面は**確定した実績を読むための画面**であり、値の修正は行わない（修正は S-01 の過去日表示 F-106 で行う）。

リストはプランとログを兼ねる（C-7）ため、ログそのものは S-01 と同じデータである。本画面が足すのは「実行済みだけを時系列で読める形」「やらなかった数」「どの種類の活動に時間を使ったかの集計」の3点。

**本画面の表示ではルーチン展開（F-301）も自動セクション移動（F-113）も行わない**。どちらも S-01 の表示時処理であり、読むだけの画面がタスクを増やしたり並びを変えたりしないようにする。

## 2. レイアウト

```
┌────────┬─────────────────────────────────────────────────────┐
│ Hitosuji│ レビュー                                             │ ← 画面見出し(h1)
│        │ ◀ 2026-07-16(木) ▶ [今日へ]  [日|週|月]              │ ← 日付ナビ＋期間切替
│ デイリー │ 実行 12件 / 実績 8:20 / 先送り 2件                   │ ← サマリ
│ ルーチン │─────────────────────────────────────────────────────│
│ マスタ  │ 実績ログ                                             │ ← F-501
│ レビュー │ 06:30-06:48 朝食         仕事  0:20 → 0:18 (-0:02)  │
│        │ 08:05-08:35 メールチェック 仕事  0:30 → 0:30          │
│        │ ...                                                 │
│        │ 先送り（2件）                                        │ ← F-502
│        │ ・タスクA ・タスクB                                   │
│        │ モード別集計          プロジェクト別集計               │ ← F-503
│        │ 仕事    5:20  64%     ブログ運営 1:30  18%           │
│        │ 暮らし  2:10  26%     （未設定）  6:50  82%          │
└────────┴─────────────────────────────────────────────────────┘
```

- 装飾のないテーブル型リスト（N-05）。S-01 と同じ書式・同じ列幅感覚で読めるようにする
- **モード色は S-01 と同じく行全体のテキスト色に反映する**
- 上から「実績ログ → 先送り → 集計」の順。1日の出来事を読んでから数字を見る流れにする

## 3. 表示内容

### 3.1 日付ナビ・期間切替

| 項目 | 仕様 |
|---|---|
| 初期表示 | 今日 |
| 日付ナビ | S-01 と同じ（前/次/今日へ）。表示中の期間の単位で前後に動く |
| 期間切替 | 日 / 週（月曜始まり）/ 月。**日次のみ稼働中で、週・月は F-506（Phase 3）**（要件定義書 §5.5） |
| 日付の保持 | S-01 と S-04 の表示日は連動させない（それぞれ独立に持つ） |

### 3.2 サマリ

| 項目 | 仕様 |
|---|---|
| 実行件数 | 期間内の実行済みタスク（`started_at` あり）の件数 |
| 実績合計 | 実績時間の合計（§3.3 の定義） |
| 先送り | §3.4。表示日が**今日以降**のときは出さない |

### 3.3 実績ログ（F-501）

| 項目 | 仕様 |
|---|---|
| 対象 | 表示期間の**実行済みタスク**（`started_at` あり）。未実行タスクは §3.4 で数えるのでここには出さない |
| 並び | `started_at` の昇順。セクションではグループ化しない（時系列で読むため） |
| 列 | 開始-終了 / タスク名 / モード / プロジェクト / 見積 / 実績 / 差異 |
| 差異 | 実績 − 見積（超過は警告色）。**見積もり未設定（0分）の行は差異を出さない**（比べる相手がないため） |
| 実績時間 | `ended_at − started_at`。**実行中（`ended_at` なし）の行は実績・差異を空にし、終了時刻を `--:--` とする**（実績が確定していないため集計にも含めない） |
| 見積もり未設定 | S-01 と同じく薄色で `--:--` |
| 週・月表示 | 日付列を先頭に足し、日をまたいで時系列に並べる |
| 0件のとき | 「実行したタスクはありません」と表示する |

コメント列は F-206（Could・未実装）の実装後に追加する。

### 3.4 先送り（F-502）

| 項目 | 仕様 |
|---|---|
| 定義 | **表示日に残っている未実行タスク（`started_at IS NULL`）の件数**。「1分でも手をつけたら先送りではない」（先送りゼロの原則） |
| 内訳 | 件数に続けてタスク名を並べる（「何を先送りしたか」が振り返りの主眼のため） |
| 他日へ移した分 | 数えない。先送り（F-107）は `task_date` の付け替えであり、移動先の日のタスクとして数えられる（要件定義書 §5.5） |
| 今日以降 | **表示しない**。まだ実行される可能性があり、先送りとして確定していないため |
| 0件のとき | 「先送りはありません」と表示する |
| 週・月表示 | 期間内の各日の合計。今日以降の日は含めない |

### 3.5 集計（F-503）

| 項目 | 仕様 |
|---|---|
| 軸 | モード別・プロジェクト別の2表を横並び |
| 値 | 実績時間の合計と、期間の実績合計に対する割合（整数%） |
| 並び | 実績時間の降順 |
| 未設定 | 「（未設定）」の行として最後に出す |
| 実績0分の軸 | 行にしない（未設定を含む。打刻直後の0分が並ぶのを避ける） |
| 0件のとき | 「集計する実績がありません」と表示する |
| アーカイブ済みマスタ | 過去タスクから参照されるため集計に含める（名前をそのまま表示する） |
| 視覚化 | 数表のみ。グラフは作らない（N-05） |

## 4. 操作

読み取り専用の画面であり、更新操作を持たない（楽観的更新の対象外）。

| ID | 操作 | 仕様 |
|---|---|---|
| O-1 | 日付・期間の移動 | §3.1。URL のクエリに表示日を持ち、リロードで同じ日を再現できる |
| O-2 | S-01 へ移動して直す | 実績ログの行から、その日の S-01 を開ける（修正の導線。行のクリック） |

## 5. キーボードショートカット

日付移動のみ S-01 と揃える。他の操作がないため独自のキーは設けない。

| キー | 操作 |
|---|---|
| `Shift+H` / `Shift+L` / `T` | 前 / 次 / 今日へ移動（表示中の期間の単位） |

共通規約は[共通](./00_共通.md) §3 が正。

## 6. 決定ログ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-07-21 | 実績ログは実行済みタスクのみを時系列で並べ、セクションでグループ化しない | セクション区切りで未実行も含めると S-01 の過去日表示とほぼ同じ画面になり、別画面にする意味がなくなるため |
| 2026-07-21 | 先送り数は「表示日に残っている未実行タスクの件数」とする | 他日へ移した分まで数えるには移動履歴が要るが、過去は遡れない。理由は要件定義書 §8 決定ログ |
| 2026-07-21 | 今日以降の日付では先送り数を出さない | まだ実行されうるタスクを先送りと表示すると、指標として読めなくなるため |
| 2026-07-21 | 集計は数表のみとし、グラフを作らない | N-05。まず数字で足りるか運用で確かめる |
| 2026-07-21 | CSVエクスポート（F-504）を本画面の初期スコープから外す | 要求を Could へ引き下げたため（要求定義書 §10 決定ログ） |
| 2026-07-21 | 週・月の期間切替は日次の完成後に追加する | 日次の振り返りが日課であり、週月は必要性を運用で確かめてからでよいため |
| 2026-07-21 | 週・月の期間集計を F-506 として分離し Phase 3 へ移す | 日次が稼働して当面の振り返りは足りており、週月は Could として必要になってから着手する（要求定義書 §10・要件定義書 §8） |
