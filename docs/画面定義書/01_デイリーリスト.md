## 1. 画面の役割

1日のタスクリストの表示・打刻・編集を行うメイン画面。利用時間の9割以上を占めるため、**シンプルなリスト・体感即応・キーボード完結**（N-01/04/05）を最優先に設計する。初期表示は今日の日付。

## 2. レイアウト

```
┌──────────────────────────────────────────────────────────────┐
│ [デイリー] [ルーチン] [マスタ] [レビュー]                       │ ← ヘッダナビ
├──────────────────────────────────────────────────────────────┤
│ ◀ 2026-07-16(木) ▶ [今日へ]    終了予定 21:45   残 5:30      │ ← 日付ナビ+サマリ
├──────────────────────────────────────────────────────────────┤
│ ＋ [ タスク名を入力して Enter で追加                        ] │ ← クイック追加欄（常設）
├──────────────────────────────────────────────────────────────┤
│ ■ 未分類                                                      │ ← インボックス（追加直後の受け皿）
│ ・┃買い出しメモ           --:--                               │ ← 見積もり未設定（薄色表示）
│ ■ 朝 6:00-9:00                          見積 2:30/3:00 (-0:30)│ ← セクション見出し
│ ✔ ┃朝食            仕事  0:20 → 0:18   06:30-06:48          │ ← 完了タスク
│ ▶ ┃メールチェック   仕事  0:30 (経過 0:12)  08:05-           │ ← 実行中タスク
│ ・┃日次プラン       計画  0:15                                │ ← 未実行タスク
│ ■ 午前 9:00-12:00                       見積 3:30/3:00 (+0:30)│ ← 超過は警告色
│ ・┃設計書レビュー   仕事  1:00                                │
│ ...                                                          │
└──────────────────────────────────────────────────────────────┘
```

- 装飾のないテーブル型リスト。1タスク=1行、行高は固定。**視認性のため行に余白を確保する**（2026-07-19 オーナー判断。詰めすぎない範囲でコンパクトに。N-05）
- **本文の文字サイズは1段階大きくする**（2026-07-20 オーナー判断: 常用画面のため読みやすさを優先。ただし**行の高さは変えない**＝余白で吸収する。モード名などの補助表記との相対関係は維持する）
- **列見出し行を置く**（名前 / モード / 見積 / 実績 / 実施時間）。どの数字が何かを一目で分かるようにする（2026-07-19 オーナー判断）。**見出しは行メニュー列を含めた実際の列幅と揃える**（見出しと数値がずれて見えないこと）
- **モード色は行全体のテキスト色として反映する**（タスク名だけでなく見積・実績・実施時間も含む。2026-07-19 オーナー判断: カラーバーより情報密度を上げられるため）。モード未設定の行は既定の文字色。行頭は打刻ボタン（§4）

## 3. 表示要素

### 3.1 日付ナビ・サマリ行

| 要素 | 仕様 | 要求 |
|---|---|---|
| 日付表示 | `YYYY-MM-DD(曜)`。表示日によらず同じ見た目にする（2026-07-19 オーナー判断: 日付自体の着色は視線が散るため） | F-106 |
| ◀ / ▶ / 今日へ | 前日/翌日/今日へ移動。クリックまたはショートカット。**「今日へ」ボタンは今日以外を表示中のみ表示し、通常の枠線ボタン（強調色を使わない）とする**（2026-07-20 オーナー判断: 強調色のボタンが「表示日＝今日」の状態表示に見え、逆に誤認を招いていたため。ボタンの有無自体が今日以外であることを示す） | F-106 |
| 日付指定 | 日付表示クリックでdatepicker | F-106 |
| 終了予定時刻 | 要件定義書 §5.1 F-104 の式で算出。毎分＋操作の都度再計算。24:00超過は `25:30` 形式＋警告色。当日表示時のみ表示 | F-104 |
| 残時間 | 未実行＋実行中残りの見積もり合計 | F-104補助 |

### 3.2 セクション見出し行

| 要素 | 仕様 | 要求 |
|---|---|---|
| セクション名・時間帯 | マスタ（sections）から表示。**有効なセクションはタスク0件でも常に表示する**（2026-07-19 オーナー判断: 1日の枠組みを常に俯瞰でき、空セクションへドラッグ移動もできるため）。アーカイブ済みセクションは当日タスクが属している場合のみ表示 | F-105 |
| 見積もり合計/枠/過不足 | `見積 2:30/3:00 (-0:30)`。合計>枠 のとき `(+超過分)` を警告色 | F-110 |
| セクション未指定タスク | リスト**先頭**（クイック追加欄の直下）に「未分類」グループとして表示。クイック追加直後のタスクの受け皿（インボックス）を兼ねる。**0件でも常に表示する**（受け皿として常に見えている必要があるため。2026-07-19 オーナー判断） | F-105 |

### 3.3 タスク行

| 列 | 仕様 | 要求 |
|---|---|---|
| 打刻ボタン | 円形ボタン。**押したときの動作**を表す（未実行 ▶開始 / 実行中 ■終了 / 完了 ✔（操作なし）） | F-201 |
| モード色 | 行全体（タスク名・見積・実績・実施時間）の文字色に反映する。モード未設定時は既定の文字色 | F-401 |
| タスク名 | クリックまたはショートカットでインライン編集 | F-102 |
| プロジェクト名 | 設定時のみ小さく表示 | F-402 |
| 見積もり | `H:MM`。インライン編集（分整数入力）。**未設定（0分）は `--:--` を薄色で表示**し、終了予定時刻の計算に含まれていないことを視覚的に示す | F-103, F-104 |
| 実績 | 完了時 `→ 実績H:MM`。実績>見積もり は警告色。**1分未満の実績は `0:00` と表示する**（`--:--` は見積もり未設定専用の表記であり、実績には使わない） | F-202 |
| 経過 | 実行中のみ `(経過 H:MM)`。クライアントタイマーで毎分更新（通信なし） | F-205 |
| 開始-終了時刻 | `HH:MM-HH:MM`。クリックでインライン修正（開始≦終了をバリデーション）。**入力は区切り文字なしでも受け付ける**（`1935` → `19:35`、`935` → `9:35`。2026-07-19 オーナー判断: 数字だけで打てるほうが速い） | F-203 |
| コメント | (Phase 3) アイコン表示＋ホバー/展開 | F-206 |

### 3.4 クイック追加欄（常設）

| 項目 | 仕様 | 要求 |
|---|---|---|
| 位置 | 日付ナビ直下に**常時表示**（モーダルや展開操作を挟まない） | F-102, N-01 |
| 入力項目 | **タスク名のみ**。見積もり・モード・プロジェクトは追加後にインライン編集で設定する（Phase 3 の F-108 補完導入時に属性引き継ぎを追加） | F-102 |
| 追加動作 | Enter で追加。欄はクリアされフォーカスは欄に残る（**連続追加**）。空のまま Enter は何もしない。Esc でフォーカスを外しリスト操作へ戻る | F-102 |
| 配置先 | **未分類グループ（リスト先頭）の末尾**に追加される（表示中のどの日付でも同じ）。ユーザーが見積もりを入力し、任意のセクション・位置へ移動してトリアージする | F-105 |
| 既定値 | 見積もり未設定（0分）・モード/プロジェクトなし・未実行 | F-103 |

**参考（旧TCC1の挙動）**: 常設入力欄にタスク名を入力して Enter → タスクリストのトップ（セクションなし）に追加 → 見積もり時間を入力し、リスト内の任意の位置へユーザーが移動する、というフローだった。本仕様はこのフローを踏襲する。フロー自体の改善（例: Phase 3 の入力補完 F-108 による見積もり・分類ごと追加、追加タスクを現在のセクションへ直接送るショートカット）は運用開始後に検討する。

## 4. 操作仕様

更新操作は原則として楽観的更新（即UI反映 → 非同期永続化、失敗時トースト＋ロールバック）とする（N-01）。

**楽観的更新の対象外**（2026-07-19 オーナー判断）: 中断（O-4）・複製（O-11）・先送り（O-7）は、生成されるタスクの `sort_order` をサーバが全タスクを見て決めるためクライアントで予測できない。サーバ確定を待って反映する。N-01 が体感0msを求める打刻・追加・並び替え（ドラッグ＆ドロップ、`Shift+J/K`、セクション割当）は楽観的更新の対象とする。

| # | 操作 | 仕様 | 要求 |
|---|---|---|---|
| O-1 | タスク追加 | 画面トップの**常設クイック追加欄**（§3.4）から行う。`N` キーで欄にフォーカス。Enter 追加・連続追加・Esc 復帰は §3.4 のとおり。セクション末尾ボタンや行挿入は設けない（途中に置きたい場合は追加後に並び替え O-6） | F-102 |
| O-2 | 開始 | 未実行タスクで開始操作 → `started_at = now`。**実行中タスク A が他にあれば割り込みとして扱う**: A を自動終了し、A の再開タスク（残り見積もり）を開始タスクの直下に自動生成してから開始する（同時実行は常に1件。データモデル定義書 §4.2-b） | F-201 |
| O-3 | 終了 | 実行中タスクで終了操作 → `ended_at = now` | F-201 |
| O-4 | 中断 | 実行中タスクで中断操作 → 現在時刻で終了し、残り見積もり `max(見積−実績, 1分)` の同名・同属性タスクを直後に自動生成 | F-204 |
| O-5 | 編集 | タスク名・見積もり・時刻はインライン編集。モード・プロジェクト・セクションは行の編集ポップオーバー（最小限のUI）で選択 | F-102/103/203 |
| O-6 | 並び替え | ドラッグ＆ドロップ、または選択状態で `Shift+J/K`（`Shift+↓/↑` でも可）。セクションをまたぐ移動でsection_idも変更 | F-101/102 |
| O-7 | 先送り | 未実行タスクに対して翌日へ移動（`task_date+1`、`postponed_count+1`）。**行メニューからのみ実行できる（先送りは簡単にできるべきではないため、ショートカットは意図的に割り当てない）**。実行中・完了タスクには不可 | F-107 |
| O-8 | 削除 | 行メニューまたは `D`。未実行は即削除（Undoトースト5秒）、打刻済みは確認ダイアログ。直前の削除は `U` またはトーストのボタンで取り消せる。**ルーチン由来のタスクを削除した場合はその日のスキップとして記録し、再表示しても復活しない**（F-304。取り消すとスキップも解除される。データモデル定義書 §3.6） | F-102, F-304 |
| O-9 | 日付移動 | `Shift+H` 前日 / `Shift+L` 翌日 / `T` 今日 | F-106 |
| O-10 | 名前補完 | (Phase 3) タスク名入力中に過去タスク名を候補表示。選択で直近実績の属性（見積もり・モード・プロジェクト・セクション）を引き継ぐ | F-108 |
| O-11 | 複製 | `Y` または行メニュー。**複製後は選択行を複製されたタスクへ移す**（続けて見積もり編集や開始打刻へ進めるため。2026-07-19 オーナー判断）。選択タスク（状態不問）を複製し、未実行タスクとして**未実施のトップ**（実行中タスクの直後、なければ最初の未実行タスクの直前、いずれもなければリスト末尾）に挿入する。名前・見積もり（満額）・モード・プロジェクトを引き継ぎ、セクションは挿入位置に従う。routine_id・split_parent_id・コメントは引き継がない（要件定義書 §5.1 F-111） | F-111 |
| O-12 | ルーチン化 | 行メニューから「ルーチン化」（**Phase 2 / F-305**）。選択タスクを雛形にルーチンを作る。名前・見積もり・モード・プロジェクトを引き継ぎ、ポップオーバーで**繰り返し種別と開始想定時刻だけ**を確認して作成する（詳細は §4.1）。ショートカットは割り当てない（頻度が低く、誤操作でルーチンが増えると後片付けが要るため。先送り O-7 と同じ理由） | F-305 |

### 4.1 ルーチン化ポップオーバー（O-12 / F-305, Phase 2）

> 2026-07-20 オーナー判断で確定（FB-11）。**ルーチンへの登録し直しが重い**という実運用の課題に対し、デイリーの文脈を離れずに最小の入力で作れることを目的とする。

**引き継ぐ値**（入力させない）: 名前・見積もり・モード・プロジェクト。`routine_id` / `split_parent_id` / コメントは引き継がない。終了日なし（無期限）・有効で作成する。

**入力させる値**（ポップオーバー。M/P/S と同じ最小UI）:

| 項目 | 既定値 | 備考 |
|---|---|---|
| 繰り返し種別 | 毎日 | 週次 / 月次 / n日ごと も選べる |
| 曜日（週次のみ） | 元タスクの `task_date` の曜日 | 複数選択可・1つ以上必須 |
| 日（月次のみ） | 元タスクの `task_date` の日 | |
| 間隔（n日ごとのみ） | 2日 | 正整数 |
| 開始想定時刻 | **元タスクの開始打刻時刻**（`HH:MM`。秒は切り捨て） | 未打刻ならタスクが属するセクションの開始時刻。未分類かつ未打刻なら現在時刻 |

| 項目 | 仕様 |
|---|---|
| 開始日 | **翌日**（`task_date + 1`）。元タスクが今日のリストに既にあるため、当日に再展開して同名タスクが2件並ぶのを防ぐ（画面定義書02 O-1 の「今日からの展開が不要な場合は開始日を翌日に」と同じ考え方） |
| 見積もり0分（未設定）の扱い | ルーチンは見積もり1分以上が必須（画面定義書02 §5）。**実績があれば実績の分数**を見積もりとする。実績もない（未実行かつ見積もり0分）場合は**作成せずエラー**「見積もりを入力してからルーチン化してください」を表示する |
| ルーチン由来タスク | 元タスクに `routine_id` があるときは**行メニューに「ルーチン化」を出さない**（既にルーチンがあるため。変えたい場合は S-02 で当該ルーチンを編集する） |
| 楽観的更新 | **対象外**。サーバ確定を待って結果を出す（デイリーの表示内容は変わらないため即時反映の必要がない。§4 の対象外リストと同じ扱い） |
| 完了後の通知 | トースト「「〇〇」をルーチン化しました（明日から展開）」 |

## 5. 行選択モデル（キーボード操作の基盤）

- リスト上に常に「選択行」が1つ存在する（初期値: 実行中タスク、なければ最初の未実行タスク）
- `↑/↓` または `J/K` で選択行を移動。各ショートカットは選択行に作用する
- `C`（Current）でいつでも選択行を「現在地」へ戻せる: 実行中タスクがあればそのタスク、なければリスト表示順で最初の未実行タスク（いずれもなければ何もしない）。**初期選択と同じ規則**であり、下方のプラン作業や過去日閲覧から打刻ループへ復帰する用途
- マウス操作とキーボード操作は等価（クリックで選択も移動する）

## 6. キーボードショートカット一覧（ドラフト）

> **2026-07-19 オーナーレビューにより確定**（要件定義書 §8-1）。変更する場合は本表を先に更新する。

| キー | 操作 |
|---|---|
| `↓` / `↑`（`J` / `K`） | 選択行の移動 |
| `C` | 現在地へジャンプ（実行中タスク、なければ最初の未実行タスク。Current） |
| `Enter` | 選択タスクの 開始 →（実行中なら）終了 のトグル |
| `I` | 中断（実行中タスクのみ） |
| `N` | クイック追加欄へフォーカス（Enter で連続追加、Esc でリストへ戻る） |
| `R` または `F2` | タスク名編集（Rename） |
| `E` | 見積もり編集（Estimate） |
| `B` / `F` | 開始時刻 / 終了時刻のインライン修正（Begin / Finish） |
| `M` | モード選択ポップオーバー |
| `P` | プロジェクト選択ポップオーバー |
| `S` | セクション選択ポップオーバー（Section） |
| `Shift+J` / `Shift+K`（`Shift+↓/↑` でも可） | タスクの並び替え（下へ / 上へ） |
| `Y` | 選択タスクの複製（未実施のトップに挿入。vim の Yank） |
| `D` | 削除 |
| `U` | 直前の削除を取り消し（Undo。Undoトーストのボタンと同等） |
| `Shift+H` / `Shift+L` / `T` | 前日 / 翌日 / 今日へ移動 |
| `?` | ショートカット一覧の表示 |

- **ルーチン化（O-12）にもショートカットを割り当てない**（先送りと同じく、誤操作で増えると後片付けが要る操作のため。行メニューから実行する）
- **`?` のヘルプ一覧には各キーのニーモニック由来を併記する**（2026-07-20 オーナー判断: 覚え直しの助けになるため。本表の括弧書き（Rename / Estimate / Begin / Finish / Current / Section / Yank / Undo）と対応させる）
- **先送り（O-7）にはショートカットを割り当てない**（誤操作で簡単に先送りできてしまうことを防ぐ意図。行メニューから実行する）
- テキスト入力中はショートカット無効（Esc で入力を抜けてから有効化）
- **IME変換中のキーは操作として扱わない**（全画面共通）。日本語入力の変換確定 `Enter` が保存・確定として発火しないよう、`isComposing` 中の `Enter` / `Escape` は無視する
- **修飾キーは Shift のみ使用し、ブラウザ既定動作の抑止（preventDefault）を最小化する**（2026-07-19 方針決定）。`Cmd/Ctrl` 系・`Space`（ページスクロール）は使用しない
- 選択移動が `J/K`、その Shift 版が並び替え、`Shift+H/L` が日付（左右）移動、と vim の HJKL 体系で統一する
- Phase 3 のコメント編集（F-206）には `Shift+C` を予約しておく（`C` は現在地ジャンプに使用）
- ポップオーバー（M/P/S）内の候補選択は Phase 1 ではクリックのみ。矢印キー＋Enter での操作は F-112（Could）で扱う
- 完了済みタスクへの `Enter` は Phase 1 では無効。「もう一回」は `Y`（複製）→ `Enter`（開始）で行う。1操作化は F-208（Could）で扱う

## 7. 表示・性能要件

| 項目 | 仕様 |
|---|---|
| データ取得 | 表示日1日分のタスク＋マスタのみ取得（N-01, N-08）。日付移動時に隣接日をプリフェッチ |
| 打刻できる日付 | **表示日によらず打刻できる**（2026-07-19 オーナー判断）。深夜作業で前日のタスクを開始・終了する運用を許容する。打刻される時刻は常に実時刻であり、ずれは F-203 の時刻修正で直す |
| ルーチン展開 | 日付リクエスト時にサーバで実行（冪等）。要件定義書 §5.3 |
| タイマー表示 | 経過時間・終了予定はクライアント計算。打刻時刻はサーバ時刻ではなく**クライアントの現在時刻**を送信（オフライン考慮不要のため単純化） |
| 空状態 | タスク0件の日でもセクション見出しは表示する。タスクが1件もない旨はクイック追加欄の案内で示す |

## 8. バリデーション・エラー

| ケース | 挙動 |
|---|---|
| 開始 > 終了 となる時刻修正 | インラインでエラー表示し確定不可 |
| 見積もりに非数値/負値 | 確定不可 |
| クイック追加欄が空（または空白のみ）で Enter | 何もしない（タスクは作られない） |
| 永続化失敗（ネットワーク等） | トースト「保存に失敗しました」＋UIロールバック。リトライは手動 |
| トーストの消え方 | **すべてのトーストは自動で消え、閉じるボタン（×）でも消せる**（2026-07-20 オーナー判断: エラートーストが残り続けて画面を塞いでいたため）。表示時間は Undo 付き5秒 / エラー8秒（エラーは読む時間が要るため長く取る） |
| 別PCとの同時操作の競合 | Phase 1 では楽観的更新の後勝ちを許容（同時に触る運用は想定しない）。実害が出たら再検討 |
| 日をまたぐ実行中タスク（就寝タスク等） | ended_at は実時刻で記録し、タスクは開始日（task_date）に属したまま。翌日リストには表示しない |
| 実行中タスクが前日以前に放置されている | 当日リスト上部に警告バナー「前日以前の実行中タスクがあります」を表示し、該当日へのリンクを置く（終了打刻の失念対策） |
