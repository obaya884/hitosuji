# 画面定義書 S-00: 全画面共通

- 版数: 1.0
- 更新日: 2026-07-21
- 対応要求: N-01（体感即応）, N-04（キーボード操作）, N-05（シンプルなUI）, N-11（操作結果の通知）
- 上位文書: [要件定義書](../要件定義書.md)

全画面に共通する枠組み・UI部品・作法を定める。各画面定義書（01〜04）はここを参照し、同じ内容を再掲しない。

---

## 1. 全体レイアウト

```
┌────────┬─────────────────────────────────────────────┐
│Hitosuji│ 画面見出し(h1)                              │
│        │                                             │
│ デイリー │ 本文（中央寄せ・最大幅）                     │
│ ルーチン │                                             │
│ マスタ  │                                             │
│ レビュー │                                             │
└────────┴─────────────────────────────────────────────┘
  ↑ Navigation Rail（画面に固定）
```

| 項目 | 仕様 |
|---|---|
| Navigation Rail | 左サイドに縦並び。項目は デイリー / ルーチン / マスタ / レビュー。**ラベルのみでアイコンは使わない**。現在地はレールの項目に表示する |
| レールの固定 | 画面に固定し、本文をスクロールしても常に見える |
| 本文 | 中央寄せ・最大幅。レール導入後も幅は変えない |
| 画面見出し（h1） | 各画面の本文先頭に置く（S-01「デイリー」/ S-02「ルーチン」/ S-03「マスタ管理」/ S-04「レビュー」）。レールに現在地があっても本文側にも示す |
| ログイン画面 | 設けない（Basic認証はブラウザ標準ダイアログ） |

## 2. 共通UI部品

### 2.1 ポップオーバー

モーダルは最小限とし、選択・入力はその場に開くポップオーバーで行う（N-05）。

| 項目 | 仕様 |
|---|---|
| 閉じ方 | `Esc` キーと、外側のクリック |
| 表示位置 | 既定は起点の**下**に開く。**下に入りきらず、かつ上の余白の方が広いときだけ上向きに反転する**。位置は開いた直後に1回だけ決め、開いている間はスクロールしても動かさない |
| 候補選択 | クリック、または `J`/`K` で候補移動して Enter で確定・Esc で取消（開くと現在値をハイライト）。矢印キーは使わない（FB-33）。詳細は S-01 §6（F-112） |
| 文字色 | 通常色（`text-ink`）。行内に開く場合でも行のモード色（F-401）は継承しない（FB-38） |

### 2.2 トースト（N-11）

操作の結果は画面を止めずにトーストで知らせる。確認が要る破壊的操作（打刻済みタスクの削除・マスタの物理削除）だけは事前確認を挟む。

| 項目 | 仕様 |
|---|---|
| 用途 | 操作の取り消し（Undo。F-115）・完了通知・エラー通知 |
| 消え方 | **すべて自動で消え、閉じるボタン（×）でも消せる** |
| 表示時間 | Undo 付き・完了通知は5秒 / エラーは8秒（エラーは読む時間が要るため長く取る） |
| 位置 | 画面下部中央。複数出る場合も重ならないよう1箇所に積む |

### 2.3 インライン編集

一覧の値はセルをクリックしてその場で編集する（編集ボタンを都度押さない）。

| 項目 | 仕様 |
|---|---|
| 確定 | `Enter` または入力欄からフォーカスが外れたとき |
| 取消 | `Esc`（元の値に戻す） |
| 変更なしの確定 | 何も送信せず閉じる |
| 保存中 | 同じ行の他のセルは編集できない（古い値での上書きを防ぐ） |
| 失敗時 | 編集状態のまま残し、入力し直せるようにする |

## 3. キーボード操作の共通規約

- **修飾キーは Shift のみ使用**し、ブラウザ既定動作の抑止（`preventDefault`）を最小化する。`Cmd/Ctrl` 系・`Space`（ページスクロール）は使わない
- **IME変換中のキーは操作として扱わない**。日本語入力の変換確定 `Enter` が保存・確定として発火しないよう、`isComposing` 中の `Enter` / `Escape` は無視する
- テキスト入力中は画面のショートカットを無効にする（`Esc` で入力を抜けてから有効化）
- 画面固有のショートカットは各画面定義書が定める（S-01 は §6）

## 4. 更新の作法

- 更新操作は原則として**楽観的更新**（即UIに反映 → 非同期で永続化、失敗時はトースト＋ロールバック）。適用範囲と対象外は要件定義書 §6 N-01 が正
- 永続化に失敗したときのメッセージは「保存に失敗しました」。リトライは手動
