## 1. 本書の位置づけ

要求定義書の要求（F-XXX / N-XX）を、実装可能な要件（機能要件・方式・画面・データ）に落とし込む。画面の詳細仕様は画面定義書に、データ構造はデータモデル定義書に分割し、本書は全体方針・要件一覧・トレーサビリティを担う。

## 2. システム方式

### 2.1 全体構成

```
[ブラウザ]
        │ HTTPS + Basic認証
        ▼
[Webアプリ: Next.js (App Router, TypeScript)]  ← Vercel (無料枠) にデプロイ
        │ SQL (Drizzle ORM)
        ▼
[DB: Neon (マネージドPostgreSQL, 無料枠)]
```

### 2.2 技術スタック選定

| レイヤ | 採用 | 選定理由（対応する非機能要求） |
|---|---|---|
| フレームワーク | Next.js (App Router) + TypeScript | フロント/APIを1リポジトリで完結でき個人開発の維持コストが低い（§9 制約）。情報量が多くAI支援と相性が良い |
| UI | React + Tailwind CSS | 装飾を排したシンプルなリストUI（N-05）を最小工数で構築。コンポーネントライブラリは原則使わない |
| データ取得/更新 | Server Actions + SWR（楽観的更新） | 打刻・追加操作の体感即応（N-01）。操作は即UIに反映し、裏で永続化する |
| ORM | Drizzle ORM | 標準SQLに近くロックインが薄い（N-06②）。マイグレーションをコードで管理 |
| DB | Neon (PostgreSQL) | 無料枠で十分（N-07）。`pg_dump` による標準形式バックアップ（N-06①）。素のPostgresなので他DBaaS/自宅サーバへ移行可能（N-06②） |
| ホスティング | Vercel 無料枠 | Next.jsと親和性が高くデプロイが自動化される（N-02, N-07） |
| 認証 | Basic認証（`src/proxy.ts` で実装、資格情報は環境変数） | シングルユーザーの簡易認証で十分（N-03）。ログイン画面の実装が不要 |

**コールドスタート**: Vercel関数とNeonのスケールトゥゼロにより初回アクセスに遅延が出る。2026-07-19 の実測は初回 1.4秒 / ウォーム 0.2〜0.4秒で、**許容できる水準と判断した**（N-01 は高頻度操作の即応が本質）。実運用で不快になれば、①Neonのautosuspend時間延長、②cron ping、③別構成への移行、の順で対処する。

### 2.2.1 コード構成・テスト戦略

レイヤー構成（クリーンアーキテクチャ）・関数型DDDの規約・テスト戦略（古典学派・テストピラミッド）は[アーキテクチャ定義書](./15_アーキテクチャ定義書.md)が正。

### 2.3 リポジトリ・環境

- 単一リポジトリ `hitosuji`（本ディレクトリ）。Gitで管理し、mainブランチへのpushでVercelに自動デプロイ
- 環境は production のみ（個人利用のため staging は設けない。ローカル開発環境で代替）
- DBマイグレーションは Drizzle Kit で管理し、適用はデプロイ前に手動実行
- **本番とローカルはファビコンで見分けられるようにする**（同じ画面を2つのタブで開くため）
- **ローカルDBには本番のマスタ・ルーチンだけを流し込める**ようにする（タスク（ログ）は持ち込まない）。手段はバックアップ（N-06）のダンプの部分リストア

※ 上記2点の具体的な手順・コマンドは README を正とする。

### 5.2 実行・ログ（S-01）

| 要求ID | 要件 |
|---|---|
| F-201 | 各タスク行の開始/終了ボタンまたはショートカット1操作で `started_at` / `ended_at` に現在時刻を打刻する。実行中にできるタスクは同時に1つ。実行中タスク A がある状態で別タスク B を開始した場合は**割り込み**として扱い、①A を現在時刻で終了 ②A の再開タスク（残り見積もり。F-204 と同じ生成規則）を **B の直下**に自動生成 ③B を開始状態にする、を1操作・1トランザクションで行う |
| F-202 | 完了タスクは「実績時間（ended - started）」と見積もりを並記し、超過分を警告色で表示する |
| F-203 | 開始・終了時刻はインライン編集で `HH:MM` を直接修正できる。整合性チェック（開始 ≦ 終了）を行う |
| F-204 | 中断操作: 実行中タスクを現在時刻で終了し、同名・同属性の新タスクを直後の位置に自動生成する。新タスクの見積もり = max(元見積もり − 実績, 1分)。生成タスクは `split_parent_id` で元タスクに紐づける |
| F-205 | 実行中タスクの経過時間を1秒〜1分粒度でリアルタイム表示する（クライアントタイマー。サーバ通信はしない） |
| F-206 | （未実装）タスクごとに1行コメントを付与できる |
| F-207 | （対象外）タスクごとの長文ノート。タスク管理の範囲外と判断（要求定義書 §10） |
| F-208 | 完了済みタスクを選択中に `Enter` を押すと、そのタスクを複製（F-111）して即開始（F-201）する「複製して開始」を**1操作・1トランザクション**で行う（「もう一回」の高速化）。複製元は完了のまま残す。他に実行中タスクがあれば F-201 の割り込みをそのまま適用する。複製と同じく**楽観的更新の対象外**。開始直後の `U` は当該複製タスクの開始取消のみ（F-210）で、複製自体は未実行として残る。完了タスクの打刻ボタン（✔）は操作なしのまま（`Enter` 限定）。`Y`（複製）→ `Enter`（開始）の2操作も引き続き使える。詳細は画面定義書01 O-14・§6 |
| F-209 | 表示日より前の日付に実行中（`started_at` あり・`ended_at` なし）のタスクが残っている場合、当日リストの上部に警告バナーを出し、該当日へのリンクを置く。詳細は画面定義書01 §8 |
| F-210 | 実行中タスク（`started_at` あり・`ended_at` なし）の**開始打刻を取り消して未実行に戻す**（`started_at` を null に戻す）。表示日が今日なら、未実行として**現在時刻を含むセクションの先頭**へ並べ直す。今日でなければ並べ直さず打刻のクリアだけ行う（採番はデータモデル定義書 §4.5）。**割り込みで開始していた場合も取り消すのは当該タスク自身のみ**で、終了させた直前タスクは完了のまま・生成済みの再開タスクも残す。完了タスクは対象外。操作（`U` の割り当てと選択による切り分け）は画面定義書01 O-13 |
| F-211 | **終了打刻（実行中→完了）でタスクを完了したら、選択行を「現在地」（実行中タスク、なければ表示順で最初の未実行。`C`・初期選択と同じ規則）へ自動で送る**。終了打刻直後は実行中タスクがいないため、送り先は表示順で最初の未実行タスクになる。対象は終了打刻のみ（✔ ボタン・`Enter` の両方）で、完了タスクへの複製開始（F-208）は既に生成タスクへ選択が移るため対象外。送り先の未実行タスクがなければ選択は完了行に据え置く。詳細は画面定義書01 §5 |
| F-212 | （未実装）完了タスク（`ended_at` あり）を**未実行に戻す**（`started_at`・`ended_at` をともに null にする）。表示日が今日なら未実行として**現在時刻を含むセクションの先頭**へ並べ直し、今日でなければ並べ直さず打刻のクリアだけ行う（F-210 と同じ規律。採番はデータモデル定義書 §4.7）。**中断・割り込みで生成された再開タスク（`split_parent_id`）や、割り込みで終了させた直前タスクには波及しない**（F-210 と同じ）。実績（開始・終了時刻）を破棄する操作のため、**戻した直後は取り消して完了状態へ復帰できる**（開始・終了時刻とセクション・並び順を戻す）。取り消しの保留は削除（F-115）と共通の1スロットで持つ。操作（`U` の割り当てと選択による切り分け）は画面定義書01 O-15 |

### 5.3 ルーチン（S-02）

| 要求ID | 要件 |
|---|---|
| F-301 | 繰り返しルール: 毎日 / 週次（曜日複数指定・**週間隔 n 週おき指定可**。1=毎週・2=隔週…）/ 月次（日指定）/ n日ごと。展開はデイリーリストの**表示のたび**にサーバ側で実行し（対象は**当日以降の日付のみ**。過去日は展開しない）、未展開のルーチンのみタスク生成する。`(routine_id, task_date)` のユニーク制約で冪等にする（データモデル定義書 §4.1） |
| F-302 | ルーチンは名前・見積もり・**開始想定時刻**・モード・プロジェクトを持つ。展開時は開始想定時刻の昇順にタスクを生成し、開始想定時刻を含むセクションへ配置する（**セクション・並び順はルーチンのデータとして持たず導出**）。開始想定時刻は並び決め用であり、実行を固定する予約時刻ではない |
| F-303 | 一覧での確認・編集・有効/無効トグル・削除ができる。無効化したルーチンは以後展開されない（既存タスクには影響しない） |
| F-304 | **特定日スキップ**: 展開されたタスクを削除したとき、その (routine_id, task_date) をスキップとして記録し、以後その日は再展開しない（データモデル定義書 §3.6・§4.1）。削除を取り消すとスキップも解除される。ルーチン本体・他の日の展開には影響しない。**個別変更（その日だけ見積もりや時刻を変える）は未実装**（展開済みタスクを直接編集すれば足りるため、専用機能の要否は運用で見極める） |
| F-305 | ログからのルーチン化。S-01 の行メニューから、選択タスクの属性を引き継いだルーチンを作る。入力させるのは繰り返し種別と開始想定時刻のみ。詳細は画面定義書01 §4.1 |
| F-306 | ルーチン一覧を列見出しのクリックで並べ替えられる。並べ替えはクライアント側で行う（一覧は全件保持しており再取得は不要）。対象の軸・既定値・第2キーなどの詳細は画面定義書02 §3.1 |
| F-119 | （未実装）関連ルーチンを**バンドル**として束ね、デイリー上で1つの流れ（左ガターの縦線）として視覚化し、束ねの最中に非メンバーを開始する割り込みを検知して知らせる。設計は[31_バンドル検討.md](../検討/31_バンドル検討.md)が正で、要件・データモデル・画面への詳細展開は実装時に行う |

**展開済みタスクとルーチンの関係**: ルーチン編集は未来の展開分にのみ反映される。展開済みタスクは独立したレコードであり遡って変化しない（ログの不変性を優先）。

### 5.4 分類（S-03）

| 要求ID | 要件 |
|---|---|
| F-401 | モードは名前と色を持つマスタ。タスク行は**モード色を行全体のテキスト色**として反映する（モード未設定の行は既定の文字色。詳細は画面定義書01 §2・§3.3） |
| F-402 | プロジェクトは名前を持つマスタ。タスクに0または1つ設定できる。デイリーのタスク行では**モードと同じく独立した列**として表示する（タスク名への併記にしない。詳細は画面定義書01 §3.3） |
| F-404 | （未実装）モード/プロジェクトによるフィルタ表示。着手時に詳細化 |
| F-405 | アーカイブ済みかつ参照0件のマスタに限り、物理削除できる。参照があるものやアーカイブしていないものには削除の導線を出さない。詳細は画面定義書03 §4.1 |

- マスタは削除ではなくアーカイブを基本とする（過去タスクからの参照を壊さないため）

### 5.5 レビュー・分析（S-04）

| 要求ID | 要件 |
|---|---|
| F-501 | 指定日の**実行済みタスク**（`started_at` あり）を開始時刻順に一覧表示する。読み取り専用のビューであり、修正は S-01 の過去日表示（F-106）で行う |
| F-502 | その日にやると決めて着手しなかったタスクの数を先送り数として表示する。**打刻の有無から導出し、先送りの履歴は持たない**。定義は画面定義書04 §3.4 |
| F-503 | モード別・プロジェクト別の実績時間（`ended_at − started_at`）合計を数表で表示する。集計対象は**表示日（日次）**。週次・月次の期間集計は F-506 |
| F-504 | （未実装）期間指定でタスクログをCSVダウンロード |
| F-505 | （未実装）見積もり精度分析。着手時に詳細化 |
| F-506 | （未実装）F-503 の集計を週次（月曜始まり）・月次の期間で切り替えて表示する。集計ロジックは F-503 と共通で、対象期間を広げる |

- 期間切替は日・週（月曜始まり）・月。**日次（F-503）のみ稼働中で、週次・月次の切替は F-506（要件バックログ・未実装）**
- F-107 の先送り（`task_date` の付け替え）で他日へ移したタスクは移動先の日に属するため、元の日の先送り数には数えない。移動の履歴は持たない（`postponed_count` は通算回数のみ）
- **F-501 のコメント列は F-206（コメント機能）の実装が前提であり、未実装のうちは対象から外す**
- UI詳細は画面定義書04 が正
