# アーキテクチャ定義書 決定ログ

レイヤー構成・DDD規約・テスト戦略の「なぜそうしたか」を日付順に残す。仕様そのものは[アーキテクチャ定義書](./15_アーキテクチャ定義書.md)が正。

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-07-26 | §8 に「テスト補助の置き場」を追加し、ドメインの型を組み立てるフィクスチャ（`task()` / `routine()` / `atJst()` / `atLocal()`）は `src/domain/<集約>/testing/` に1本だけ置いて全層から使うと定めた（T-43） | T-39 の6ワーカー並行実装で同じ道具が別々の流儀で増え、`task()` が24本・`at()` が6定義（3シグネチャ）まで分裂した。集約先の候補は「domain 配下」と「`src/app/_testing/`」の二択だったが、後者にすると **domain のテスト（node 環境）が presentation 配下を参照する形になり依存方向が逆に見える**。domain は最下層なのでどの層から参照しても方向に反さず、`src/usecases/*/testing/in-memory-repository.ts` という前例とも揃う |
| 2026-07-26 | 共有ファクトリの**既定値は中立**（`estimateMinutes: 0`・`sectionId: null`・未打刻）に固定し、テストが依拠する値は呼び出し側へ書く規約にした（T-43） | 統合前は既定が `estimateMinutes: 30` / `sectionId: 1` のファイルがあり、**本文のどこにも 30 や 1 が現れないままテストがその既定に寄りかかっていた**（読んでも何を主張しているか分からない）。中立既定へ寄せた結果、実際に「見積もり0では手前の `estimate_required` で落ちて曜日検証に届かない」等の隠れた依存が7件表面化し、すべて呼び出し側へ明示した。テスト名から仕様条項が読めることが現在の最大の美点なので、既定値でそれを損なわない |
| 2026-07-26 | 既定値の中立化には**「異常系の判別が消える」という副作用**があると分かり、§8 の規約を「呼び出し側に書く」だけでなく**「そのテストが通す前提の値も書く」**まで含めて読むことにした（T-43） | `test-reviewer` が実際の劣化を1件見つけた——`from-task.test.ts` の「ルーチン由来からは作成できない」と「ルーチン由来の判定は見積もりチェックより優先する」が、`estimateMinutes` の既定を 0 にした結果**完全に同じ入力・同じ期待値**になり、後者が「優先する」を証明できなくなっていた（実装を `routineId !== null && estimateMinutes === 0` に壊しても両方緑）。中立既定は「暗黙の依存を炙り出す」効果と引き換えに「**手前のガードで落ちて本題に届かないテスト**」を作りうる。落ちたテストを直すだけでは足りず、**落ちなかったテストが依然として別物を主張しているか**を見る必要がある |
| 2026-07-26 | 打刻時刻の組み立てを `atJst()` と `atLocal()` に**名前で分けた**（同じ `HH:MM` 文字列を取る同一シグネチャ）（T-43 / T-47） | 表示側の `format.ts` は `APP_TIME_ZONE = Asia/Tokyo` 固定、入力の解釈側 `applyClockTime` は `Date#setHours` ＝ローカル、という非対称が現にある（根の解消は T-47）。統合前は同名 `at()` が JST 版とローカル版の**2つの契約で並存**しており、素朴に一方へ寄せると JST の手元では通り UTC の CI だけが落ちる。シグネチャを揃えたのは、テストを書くとき選ぶべきは「タイムゾーンの意味」だけで、書式まで変わると呼び分けの判断が濁るため |
| 2026-07-26 | 基準日を `TEST_DATE = 2026-07-26`（日曜）1つに統一し、曜日そのものに依拠するテストだけが自前の日付を持つことにした（T-43） | 共有ファクトリの `taskDate` 既定と、テストがユースケースへ渡す表示日が食い違うと、各呼び出しで `taskDate` を上書きする羽目になり集約の意味が消える。統合前は層ごとに 07-19 / 07-20 / 07-26 の3つがあったので、既存の app 層に合わせて 07-26 に寄せ、domain・usecases 側は**曜日を保ったまま +7日**ずらした（07-19 も 07-26 も日曜） |
| 2026-07-26 | マスタ固定値（`MODES` / `PROJECTS` / `SECTIONS`）は**統合しない**と決め、プリセット外の色を `MODE_COLORS` 参照へ直すだけに留めた（T-43） | 4セットの中身が違うのは不揃いではなく、各シナリオが必要とする条件（アーカイブ済みを含むか・id 体系・時間帯の並び）そのもの。1セットへ寄せると「このテストは何に依拠しているか」が本文から消え、上の中立既定の規約と同じ失敗を別の形で作る。一方で色だけは**プリセット外の hex（`#ff0000` 等）が使われていて実データと乖離**しており、`modeColorName` のフォールバック経路を無自覚に踏んでいたため直した（T-57 と同じ根） |
