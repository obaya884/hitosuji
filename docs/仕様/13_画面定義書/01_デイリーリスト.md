## 1. 画面の役割

1日のタスクリストの表示・打刻・編集を行うメイン画面。利用時間の9割以上を占めるため、**シンプルなリスト・体感即応・キーボード完結**（N-01/04/05）を最優先に設計する。初期表示は今日の日付。

## 2. レイアウト

```
┌────────┬─────────────────────────────────────────────────────┐
│ Hitosuji│ デイリー                                             │ ← 画面見出し(h1)   ┐
│        │ ◀ 2026-07-16(木) ▶ [今日へ] ▓▓░░ 8/29             │ ← 日付ナビ+サマリ  │ sticky
│ デイリー │   終了予定 21:45 現在 16:15 残作業 5:30         [?] │   （日付の直後に続ける）│
│ ルーチン │ ＋ [ タスク名を入力して Enter で追加               ] │ ← クイック追加欄   ┘
│ マスタ  │─────────────────────────────────────────────────────│
│ レビュー │ ■ 未分類                                            │ ← インボックス（追加直後の受け皿）
│        │ ・┃買い出しメモ           --:--                      │ ← 見積もり未設定（薄色表示）
│        │ ■ 朝 6:00-9:00          合計 2:30/3:00 残り +0:12  │ ← セクション見出し
│        │ ✔ ┃朝食         仕事 0:20 → 0:18  06:30-06:48       │ ← 完了タスク
│        │ ▶ ┃メールチェック 仕事 0:30 (経過 0:12) 08:05-       │ ← 実行中タスク
│        │ ・┃日次プラン    計画 0:15                           │ ← 未実行タスク
│        │ ■ 午前 9:00-12:00       合計 3:30/3:00 残り -0:30  │ ← 残りがマイナス=警告色
│        │ ・┃設計書レビュー 仕事 1:00                          │
│        │ ...                                                 │
└────────┴─────────────────────────────────────────────────────┘
```

- 画面見出し（h1）「デイリー」を日付ナビの上に置く（[共通](./00_共通.md) §1）
- 装飾のないテーブル型リスト。1タスク=1行、行高は固定。視認性のため行に余白を確保する（N-05）
- **本文の文字サイズは1段階大きくする。ただし行の高さは変えない**（余白で吸収する）。モード名などの補助表記との相対関係は維持する
- **列見出し行を置く**（タスク / プロジェクト / モード / 見積 / 実績 / 実施時間）。**見出しは行メニュー列を含めた実際の列幅と揃える**（見出しと数値がずれて見えないこと）
- **モード色は行全体のテキスト色として反映する**（反映範囲は §3.3「モード色」）。行頭は打刻ボタン（§4）
- **画面上部（h1・日付ナビ＋サマリ行・クイック追加欄）は sticky で画面上端に固定し、下端に罫線を引く**。列見出し行は固定しない。**選択行のスクロール追従（§5）は固定領域の高さを避けて停止する**（追従した行が固定領域の裏に隠れないこと）

## 3. 表示要素

### 3.1 日付ナビ・サマリ行

**サマリは日付ナビの直後（左寄せ）に続けて並べる**。文字サイズは1段階拡大してリスト本文と同じ大きさに揃え、ラベル（「終了予定」等）は本文より1段階小さくして数値を主役にする。`?` ボタンだけは右端に置く。

| 要素 | 仕様 | 要求 |
|---|---|---|
| 日付表示 | `YYYY-MM-DD(曜)`。表示日によらず同じ見た目にする | F-106 |
| ◀ / ▶ / 今日へ | 前日/翌日/今日へ移動。クリックまたはショートカット。**「今日へ」ボタンは今日以外を表示中のみ表示し、通常の枠線ボタン（強調色を使わない）とする**（ボタンの有無自体が今日以外であることを示す） | F-106 |
| 日付指定 | 日付表示クリック、またはショートカット `G` で datepicker を開き、離れた日付へジャンプ（下の詳細） | F-117 |
| タスク進捗（1日全体） | **プログレスバー＋実施済み件数／全件数**（例: バー＋ `8/29`）。表示日の全タスク（未分類を含む全セクション）が対象。実施済みの定義・件数ベースの数え方、バーの見た目（実施済み／未実施の色）は §3.2 と同じ。**表示日によらず常に表示する** | F-114 |
| 終了予定時刻 | データモデル定義書 §4.3 の式で算出。毎分＋操作の都度再計算。24:00超過は `25:30` 形式＋警告色。当日表示時のみ表示 | F-104 |
| 現在時刻 | `HH:MM`。毎分更新（クライアント時計。通信なし）。終了予定時刻と並べる。当日表示時のみ表示 | F-104補助 |
| 残作業 | 未完了見積もり（データモデル定義書 §4.3。未実行＋実行中残りの見積もり合計）。ラベルは「残作業」とする（残りの空き時間ではなく、これからやる作業量） | F-104補助 |

- **「今日」は日界で解決する**（F-116）: 現在時刻が日界時刻より前のときは前の暦日を今日とする（例: 日界 06:00 で深夜 02:00 に開くと、今日＝前の暦日）。初期表示日・「今日へ」の遷移先・当日判定（終了予定や自動セクション移動 §4.2 の発火条件）はこの「今日」に従う。既定の深夜 00:00 では暦日と一致する。日界セクションの指定は画面定義書03 §3.1

- **日付指定（datepicker。F-117）**: 前後日・今日（F-106）だけでは遠い日付への移動が煩雑なため、カレンダーから離れた日付へ直接ジャンプする手段を持つ。
  - **開く**: 日付表示のクリック、またはショートカット `G`（Go to date）。開いたときは表示日にフォーカスを置く
  - **カレンダー**: 月グリッド。**週の起点は月曜**。`◀` / `▶` で前月 / 翌月へ移動する（年単位のジャンプは持たない）。**表示日**と**今日**（日界考慮）をそれぞれ視覚的に示す
  - **月移動時のカーソル**: `◀` / `▶` はカーソル（未確定の選択日）を**同じ日を保ったまま**前月 / 翌月へ動かす。移動先の月にその日がなければ**その月末へ丸める**（例: 1/31 で `▶` → 2月末）
  - **キーボード**: 矢印または `H`/`J`/`K`/`L` で日移動（H=前日・L=翌日・J=翌週・K=前週。移動先が表示月外なら月表示も追従）、`Enter` で確定、`Esc` で閉じる。表示中は背後の行操作キーを無効化する（[共通](./00_共通.md) §2.1 のポップオーバー規約に準じる）
  - **確定**: 日をクリック、または `Enter`。選んだ日付を表示日にして（`?date=` 遷移）カレンダーを閉じる。外側クリックでも閉じる（選択せず）

### 3.2 セクション見出し行

| 要素 | 仕様 | 要求 |
|---|---|---|
| セクション名・時間帯 | マスタ（sections）から表示。**有効なセクションはタスク0件でも常に表示する**（1日の枠組みを俯瞰でき、空セクションへも `Shift+J/K` や `S` で移せる）。アーカイブ済みセクションは当日タスクが属している場合のみ表示 | F-105 |
| タスク進捗 | **プログレスバー＋実施済み件数／全件数**（例: バー＋ `2/5`）。実施済み＝完了（`ended_at` あり）で、実行中は含めない。バーの比率も件数ベース。未分類グループにも表示する | F-114 |
| 時間合計/枠 | `合計 2:30/3:00`（配置タスクの時間合計 / セクション枠の長さ）。**分子は完了タスクは実績、未完了（実行中・未実行）は見積もりを合算する**（実行中は見積もりで数え、完了打刻で実績へ切り替わる）。日付・時刻に依らず表示する。時間合計（分子）が0のときは `--:--` | F-110 |
| 残り時間 | `残り +0:30` /（超過時）`残り -0:15`。終了予定時刻（F-104）のセクション版で、**値の式はデータモデル定義書 §4.3**。**マイナスは警告色**。現在時刻に依存するため、**表示日が今日で、かつ現在時刻がそのセクションの終了時刻より前のときだけ表示する**（今日以外・現在時刻が終了を過ぎた過去セクションでは出さない。§4.2 で決めた「現在位置」の考え方と揃える） | F-110 |
| タスク0件のグループ | **セクション名・時間帯だけを表示し、その右（進捗・時間合計・残り時間）は出さない**。「タスクなし」等の行も置かず、見出し行だけにする | F-105/110/114 |
| セクション未指定タスク | リスト**先頭**（クイック追加欄の直下）に「未分類」グループとして表示。クイック追加直後のタスクの受け皿（インボックス）を兼ねる。**0件でも常に表示する**。未分類は時間帯の枠を持たないため残り時間は出さない | F-105 |
| 現在セクションの強調 | **現在時刻が属するセクション**の見出し行だけ、背景色を通常の `band` から**専用トークン `band-now`**（`band` と同系の暖色面を一段濃くしたもの。警告の地色 `danger-weak` とは明度・彩度で離す）へ変える。文字色・罫線・レイアウトは変えない（トークン選定の経緯は決定ログ）。**表示日が今日で、かつ現在時刻がそのセクションの時間帯内のときだけ**強調する（残り時間と同じ規律）。**未分類グループとアーカイブ済みセクションは対象外**（前者は時間帯を持たず、後者は24時間の敷き詰めから外れて「現在」が定義できない）。日界をまたぐ回転順（F-116）でも判定は時間帯の包含だけで決まるため回転の影響を受けない。強調が次のセクションへ移る契機は既存の毎分再描画（`useNow`）に乗る | F-121 |
| 見出し行のレイアウト | **全要素を左寄せで1行に並べる**。並び順: `セクション名｜時間帯｜(小余白)｜進捗バー｜実施済み/合計｜(小余白)｜時間合計｜残り時間`。行の右側は空けたままにする | F-105/110/114 |

- **プログレスバーの見た目**（§3.1 のサマリ行と共通）: 実施済み部分は `accent`（紺藍）、未実施部分（トラック）は**半透明トークン `track`**（`ink` を 6% だけ地色へ重ねる。不透明色にしない——半透明なら `paper`・`band`・`band-now` のどの地色でも一定量だけ沈む。経緯は決定ログ）。**高さは細い1本のままとし、トラックに罫線は足さない**
- **セクションの並び順は日界セクションを先頭にした回転**（`(start_time − 日界 + 24h) % 24h` 昇順。F-116 / データモデル定義書 §3.1）。日界が深夜 00:00（既定）なら通常の `start_time` 昇順に一致する。日界を朝 06:00 にすれば「朝 → … → 夜 → 深夜」の並びになり、深夜（00:00–06:00）はその論理日の末尾に来る。未分類グループは回転の対象外で常にリスト先頭（クイック追加欄の直下）に置く。当日タスクが属するアーカイブ済みセクションも同じオフセットで並ぶ。**この回転はセクション見出しだけでなく、セクション選択ポップオーバー（O-5）の候補順にも同じく適用する**（見出しと選択肢の並びを一致させるため）

### 3.3 タスク行

| 列 | 仕様 | 要求 |
|---|---|---|
| 打刻ボタン | 円形ボタン。**押したときの動作**を表す（未実行 ▶開始 / 実行中 ■終了 / 完了 ✔（操作なし）） | F-201 |
| モード色 | 行全体（タスク名・プロジェクト・見積・実績・実施時間）の文字色に反映する | F-401 |
| モード未設定行の色 | **タスク名と見積は既定の文字色のまま、モード色が乗る他の値（モード・プロジェクト・セクションの併記・実績・実施時間）を副次情報の色にする**（対象の選び方の理由は決定ログ。見積は未設定の薄い表記＝[共通](./00_共通.md) §2.4 が優先） | F-401 |
| タスク名 | クリックまたはショートカットでインライン編集 | F-102 |
| モード名 | 独立した列で表示する（表示の規則は下の「プロジェクト列・モード列の共通規則」）。割り当ての入口はセルのクリック（選択ポップオーバー O-5）と `M` キー | F-401 |
| プロジェクト名 | **モードと同じく独立した列**で表示する。列の位置は**タスク名の直後・モードの左**（「何を〈タスク〉／どの件で〈プロジェクト〉／どういう性質か〈モード〉」の順）。表示の規則は下の「プロジェクト列・モード列の共通規則」。**アーカイブ済みプロジェクトも名前をそのまま表示する**（過去タスクからの参照を保つため。ルーチン一覧 §3 と同じ扱い）。割り当ての入口はセルのクリック（選択ポップオーバー O-5）と `P` キー | F-402 |
| 見積もり | `H:MM`。インライン編集（分整数入力）。**未設定（0分）は `--:--` を薄色で表示**し、終了予定時刻の計算に含まれていないことを視覚的に示す | F-103, F-104 |
| 実績 | 完了時 `→ 実績H:MM`。実績>見積もり は警告色。**1分未満の実績は `0:00` と表示する**（`--:--` は見積もり未設定専用の表記であり、実績には使わない） | F-202 |
| 経過 | 実行中のみ `(経過 H:MM)`。クライアントタイマーで毎分更新（通信なし）。**0:00 未満は表示しない**（打刻直後にクライアント時計のズレで現在時刻が開始時刻より前になっても、負値ではなく `0:00` とする。FB-28） | F-205 |
| 開始-終了時刻 | `HH:MM-HH:MM`。クリックでインライン修正（開始≦終了をバリデーション）。**入力は区切り文字なしでも受け付ける**（`1935` → `19:35`、`935` → `9:35`）。**編集を始めたときは既存の値を全選択した状態にする**（打ち直しが前提の項目のため、消す操作なしに `1210` と打てる）。**修正できるのは打刻済みの時刻だけ**——開始時刻は開始済み（実行中・完了）の行、終了時刻は完了した行でのみ編集を開ける。未打刻の側は表示もされず、クリック・`B`/`F`（§6）のいずれからも開かない | F-203 |
| 予想開始時刻 | **未実行行のみ**、開始-終了時刻と同じ位置（実施時間列）に `HH:MM-` 形式で**弱色**表示する（列は増やさない。N-05）。実打刻と同じ位置に縦に並ぶため、上から下へ時間の流れとして読める。弱色が実績（確定した記録）との区別を担う。**表示日が今日のときだけ出す**（終了予定 F-104・セクション残り時間 F-110 と同じ規律）。値は §4.3 の積み上げ（データモデル定義書）で、24:00 超過は終了予定と同じく論理日基準の折返し表記（`25:30` 形式）とするが、**行単位では警告色にしない**（行が多く騒がしくなるため。超過の警告はサマリ行の終了予定が担う） | F-120 |
| コメント | （未実装）アイコン表示＋ホバー/展開 | F-206 |

- **プロジェクト列・モード列の共通規則**（2列は同じ見た目・同じ表記に揃える。片方だけ変えない）:
  - **幅は2列とも同じ固定幅**とし、**収まらない名前は切り詰める**（折り返さない。行高は変えない。N-05）
  - 未設定の表記は[共通](./00_共通.md) §2.4 に従う（薄色の `-`。マスタ名をプレースホルダとして出さない）

### 3.4 クイック追加欄（常設）

| 項目 | 仕様 | 要求 |
|---|---|---|
| 位置 | 日付ナビ直下に**常時表示**（モーダルや展開操作を挟まない） | F-102, N-01 |
| 入力項目 | **タスク名のみ**。見積もり・モード・プロジェクトは追加後にインライン編集で設定する（補完 F-108 の導入時に属性引き継ぎを追加する） | F-102 |
| 追加動作 | Enter で追加。欄はクリアされ、**フォーカスを欄から外して追加したタスクを選択する**（そのままリスト操作・打刻へ移れる）。連続してためたいときは `A` で欄に戻る。空のまま Enter は何もしない。Esc でフォーカスを外しリスト操作へ戻る | F-102 |
| 配置先 | **未分類グループ（リスト先頭）の末尾**に追加される（表示中のどの日付でも同じ）。ユーザーが見積もりを入力し、任意のセクション・位置へ移動してトリアージする | F-105 |
| 既定値 | 見積もり未設定（0分）・モード/プロジェクトなし・未実行 | F-103 |

## 4. 操作仕様

更新操作は楽観的更新を原則とする。適用範囲と対象外（中断 O-4・複製 O-11・先送り O-7）は要件定義書 §6 N-01 が正。

| # | 操作 | 仕様 | 要求 |
|---|---|---|---|
| O-1 | タスク追加 | 画面トップの**常設クイック追加欄**（§3.4）から行う。`A` キーで欄にフォーカス。Enter 追加・追加行への選択移動・Esc 復帰は §3.4 のとおり。セクション末尾ボタンや行挿入は設けない（途中に置きたい場合は追加後に並び替え O-6） | F-102 |
| O-2 | 開始 | 未実行タスクで開始操作 → `started_at = now`。**実行中タスク A が他にあれば割り込みとして扱う**: A を自動終了し、A の再開タスク（残り見積もり）を開始タスクの直下に自動生成してから開始する（同時実行は常に1件。データモデル定義書 §4.2-b） | F-201 |
| O-3 | 終了 | 実行中タスクで終了操作 → `ended_at = now` | F-201 |
| O-4 | 中断 | 実行中タスクで中断操作 → 現在時刻で終了し、残り見積もり `max(見積−実績, 1分)`（見積もり未設定＝0分は 0 のまま。データモデル定義書 §4.2）の同名・同属性タスクを直後に自動生成 | F-204 |
| O-5 | 編集 | タスク名・見積もり・時刻はインライン編集。モード・プロジェクト・セクションは行の編集ポップオーバー（最小限のUI）で選択。**ポップオーバーは開くと現在値をハイライトし、`J`/`K` で候補移動・Enter で確定・Esc で取消**（クリックでも選べる。F-112）。**セクションの選択肢は名前の右に時間帯（`開始–終了`。終了時刻は次セクション開始の導出）を、見出し §3.2 と同じ表記（`font-mono`・弱色）で付記する**（名前だけでは時間帯が思い出せず選びにくいため。FB-46）。表示中は行操作キーを背後に流さない。**セクションの候補は先頭に「現在のセクションへ（〈セクション名〉）」を固定で置き、区切り線で実セクション候補と分ける**——下記の詳細に従う | F-102/103/203, F-112 |
| O-6 | 並び替え | 選択状態で `Shift+J/K`。セクションをまたぐ移動でsection_idも変更。**移動先は表示中のセクション順（§3.2 の回転順）に一致し、当日タスクが属するアーカイブ済みセクションも移動先に含む**（表示されているものは跨げる）。`S`（O-5）でのセクション割り当てが新規付与のためアーカイブ済みを選択肢に出さない（画面定義書03 §4）のとは対象が異なる——Shift+J/K は表示上の並べ替え、`S` は割り当て先選択という役割差による。**ドラッグ＆ドロップは提供しない**（§9 決定ログ） | F-101/102 |
| O-7 | 先送り | 未実行タスクに対して翌日へ移動（`task_date+1`、`postponed_count+1`）。**行メニューからのみ実行できる**（§6 参照）。実行中・完了タスクには不可 | F-107 |

| O-9 | 日付移動 | `Shift+H` 前日 / `Shift+L` 翌日 / `T` 今日 | F-106 |
| O-10 | 名前補完 | （未実装 / F-108 Could）タスク名入力中に過去タスク名を候補表示。選択で直近実績の属性（見積もり・モード・プロジェクト・セクション）を引き継ぐ | F-108 |
| O-11 | 複製 | `Y` または行メニュー。選択タスク（状態不問）を複製し、未実行タスクとして**未実施のトップ**（実行中タスクの直後、なければ最初の未実行タスクの直前、いずれもなければリスト末尾）に挿入する。名前・見積もり（満額）・モード・プロジェクトを引き継ぎ、セクションは挿入位置に従う。`routine_id`・`split_parent_id`・コメントは引き継がない。**複製後は選択行を複製されたタスクへ移す**（続けて見積もり編集や開始打刻へ進めるため） | F-111 |
| O-12 | ルーチン化 | 行メニューから「ルーチン化」。選択タスクを雛形にルーチンを作る。名前・見積もり・モード・プロジェクトを引き継ぎ、ポップオーバーで**繰り返し種別と開始想定時刻だけ**を確認して作成する（詳細は §4.1） | F-305 |
| O-13 | 開始の取り消し | **実行中タスクを選択中**に `U` → `started_at` をクリアして未実行に戻す。表示日が今日なら未実行として**現在位置**（§4.2 の定義。実行中タスクが別にあればその直後、なければ現在時刻を含むセクションの未実行先頭）へ置く（開始前の位置は復元しない）、今日でなければ位置はそのまま。完了タスクは対象外（完了からの巻き戻しは O-15）。採番・割り込み時の非波及の詳細はデータモデル定義書 §4.5 / 要件定義書 F-210。**`U` の切り分け（本表が正）**: 取り消しの**保留（Undoトースト表示中）があればそれを優先**、無ければ実行中タスクを選択中なら開始の取り消し、完了タスクを選択中なら完了の取り消し（O-15）、それ以外は何もしない。**保留は種類（削除 O-8 / 完了の取り消し O-15）を問わず常に1つ**で、後から来た操作が前の保留を置き換える。保留を優先するのは、削除直後は選択が現在地（実行中タスク）へ移るため優先しないと `U` が開始取消に化けるから。**置き換えが起きるのは新たな削除（`D`）のときだけ**——保留があるあいだ `U` はその解決に吸われるため、新たな完了の取り消しは発生しえない（トースト表示中は `U` が保留の解決にロックされる） | F-210 |
| O-14 | 複製して開始 | **完了タスクを選択中**に `Enter` → そのタスクを複製（O-11 と同じ引き継ぎ規則。見積もりは満額）してすぐ開始する「もう一回」。複製元は完了のまま残す。複製・開始・（他に実行中タスクがあれば）割り込み（O-2）を**1操作・1トランザクション**で行う。複製と同じく**楽観的更新の対象外**（sort_order をサーバが採番するため）。複製タスクは開始により F-113 規則aで現在位置（開始時刻を含むセクション）へ入り、**選択も複製タスクへ移す**（表示日が今日でなければ §4.2-a は適用されず複製元と同じセクションのまま。配置の詳細はデータモデル定義書 §4.6）。開始直後の `U` は当該複製タスクの開始取消のみ（O-13 / F-210）で、複製自体は未実行として残る。完了タスクの打刻ボタン（✔）は操作なしのまま（`Enter` 限定） | F-208 |
| O-15 | 完了の取り消し | **完了タスクを選択中**に `U` → `started_at`・`ended_at` を**ともにクリア**して未実行に戻す（「実施していなかった」と直す操作）。表示日が今日なら未実行として**現在位置**（§4.2 の定義。他に実行中タスクがあればその直後、なければ現在時刻を含むセクションの未実行先頭）へ置き、今日でなければ位置はそのまま（O-13 と同じ規則）。中断・割り込みで生成された再開タスクや、割り込みで終了させた直前タスクには波及しない。**実績（開始・終了時刻）を破棄するため Undoトースト（5秒）を出す**——トーストのボタン、または続けての `U` で元の完了状態（開始・終了時刻とセクション・並び順）へ復帰できる（**復帰できるのはトーストが出ているあいだだけ**。[共通](./00_共通.md) §2.2）。保留は削除（O-8）と共通の1スロットで、切り分けは O-13。楽観的更新は O-13 と同じ扱い（打刻のクリアのみ即時反映し、並べ直しはサーバ確定後）。採番はデータモデル定義書 §4.7 | F-212 |

### 4.1 ルーチン化ポップオーバー（O-12 / F-305）

デイリーの文脈を離れずに最小の入力でルーチンを作るための導線。

**引き継ぐ値**（入力させない）: 名前・見積もり・モード・プロジェクト。`routine_id` / `split_parent_id` / コメントは引き継がない。終了日なし（無期限）・有効で作成する。

**入力させる値**（ポップオーバー。M/P/S と同じ最小UI）:

| 項目 | 既定値 | 備考 |
|---|---|---|
| 繰り返し種別 | 毎日 | 週次 / 月次 / n日ごと も選べる |
| 曜日（週次のみ） | 元タスクの `task_date` の曜日 | 複数選択可・1つ以上必須。**「平日」「土日」のプリセットボタンも置く**（画面定義書02 §4 と同じ。曜日チェックが出る場所には同じ入力補助を置く） |
| 週間隔（週次のみ） | 1（毎週） | 1〜53の整数（2=隔週…）。週次選択時に曜日の下へ出す。週間隔の仕様は画面定義書02 §4・データモデル定義書 §4.1 |
| 日（月次のみ） | 元タスクの `task_date` の日 | |
| 間隔（n日ごとのみ） | 2日 | 正整数 |
| 開始想定時刻 | **元タスクの開始打刻時刻**（`HH:MM`。秒は切り捨て） | 未打刻ならタスクが属するセクションの開始時刻。未分類かつ未打刻なら現在時刻。**入力は §3.3 の打刻修正（F-203）と同じく区切り文字なしでも受け付ける**（`0805` → `08:05`）。不正な値は確定できず、ポップオーバー内にエラーを表示する |

| 項目 | 仕様 |
|---|---|
| 開始日 | **翌日**（`task_date + 1`）。元タスクが今日のリストに既にあるため、当日に再展開して同名タスクが2件並ぶのを防ぐ |
| 見積もり0分（未設定）の扱い | ルーチンは見積もり1分以上が必須（画面定義書02 §5）。**実績があれば実績の分数**を見積もりとする。実績もない（未実行かつ見積もり0分）場合は**作成せずエラー**「見積もりを入力してからルーチン化してください」を表示する |
| ルーチン由来タスク | 元タスクに `routine_id` があるときは、行メニューの「ルーチン化」を**非活性（グレーアウト・押せない）で表示する**。項目自体は見せ、その位置に操作が存在することは分かるようにする（変えたい場合は S-02 で当該ルーチンを編集する。FB-30） |
| 楽観的更新 | **対象外**（デイリーの表示内容は変わらないため即時反映の必要がない） |
| 完了後の通知 | トースト「「〇〇」をルーチン化しました（明日から展開）」 |
| 「作成」を押した後 | **ポップオーバーは即座に閉じる**（サーバ応答は待たない）。結果は完了トースト／エラートーストで示す。ローディング表示は置かない |

### 4.2 タスクの自動セクション移動（F-113）

リストを**上から「実行済みのログ → 実行中 → これからの予定」の順**に、手で並べ直さなくても保つための自動整列（C-7）。未来側は「上から順に実行していけばよい」状態を、過去側は「上から順に実行したログ」として読める状態を目指す。規則 a / b は未来側、規則 c は過去側（ログの訂正）に効く。

**対象**: 表示日が**今日**のときの、次の3つ。

1. **開始操作をしたタスク自身**（規則 a）。開始した瞬間に1回だけ移す
2. **未実行タスク**（`started_at IS NULL`）（規則 b）
3. **開始時刻を修正したタスク自身**（規則 c）。実行中・完了のいずれでも移す

| 対象外 | 理由 |
|---|---|
| 実行中タスク（開始した瞬間・開始時刻を修正した瞬間を除く） | セクションが決まった後は時刻の経過では動かさない。実行中に時間帯をまたいでも、始めた時間帯に置いたままにする |
| 完了タスク（開始時刻を修正した瞬間を除く） | 打刻の記録そのものであり、時刻が変わらない限り並びを動かさない |
| 終了時刻（F）だけを修正したとき | セクションの帰属は「いつ始めたか」で決める（規則 a と同じ基準）。深夜まで延びたタスクが深夜セクションへ飛ばないようにするため |
| 未分類（インボックス）のタスク | 「まだトリアージしていない受け皿」であり、時刻経過では動かさない。**ただし開始したとき・開始時刻を修正したときは規則 a / c で移る** |
| 今日以外の表示日 | 過去日はログとして保全し、未来日は計画として尊重する |

**移動の規則**（「現在位置」= 実行中タスクがあればその直後、なければ現在時刻を含むセクションの未実行タスクの先頭）:

| # | 契機 | 挙動 |
|---|---|---|
| a | タスクを**開始**した | 開始時刻を含むセクションへ**そのタスク自身**を移す。**未分類（`section_id IS NULL`）からも移る**。移動先での位置はそのセクションの末尾（＝実行順に積まれる）。既に開始時刻を含むセクションにいる場合は何もしない。割り込みで自動生成される再開タスクは「開始タスクの直下」に置くが、**開始タスク自身がこの規則で移動する場合は移動後の位置を基準にする**（再開タスクだけ元のセクションに取り残されないように） |
| b | 現在位置**より前**に未実行タスクがある | それらを**相対順序を保ったまま**現在位置の直後へまとめて繰り下げる。移動先のセクションに元からあるタスクよりも**前**に置く（やり残しを先に目に入れるため） |
| c | **開始時刻を修正**した（F-203） | 修正後の開始時刻を含むセクションへ**そのタスク自身**を移す。実行中・完了のいずれでも移し、未分類からも移る。移動先での位置は**開始時刻順**: 移動先セクションの打刻済みタスク（`started_at` あり）と時刻順に並ぶ位置へ挿入する（自分より遅い開始時刻の打刻済みタスク、または最初の未実行タスクの直前）。既に修正後の時刻を含むセクションにいる場合はセクションを変えないが、**同じセクション内でも開始時刻順の位置へ置き直す** |

| 項目 | 仕様 |
|---|---|
| 発火タイミング | **打刻（開始・終了）した時**、**開始時刻を修正した時**（規則 c）、**デイリーを表示した時**（サーバ側。ルーチン展開と同じ契機）。毎分の自動並び替えはしない（見ている目の前で行が動かないようにするため） |
| 取り消し | **専用のUIは設けない**（トーストも出さない）。不満なら `Shift+J/K` で戻せる |
| 移動に失敗したとき | 規則 a / b（打刻・表示が契機）は**打刻を巻き添えにしない**。エラーは表示せず、次の打刻または表示時に再試行される（冪等なため）。規則 c（打刻の修正が契機）だけは**打刻の修正と同一トランザクション**とし、移動に失敗したら修正ごと失敗させてエラーを出す（表示時に再試行できる契機がないため、時刻だけ変わって位置が置き去りになる状態を作らない） |
| 時間合計・終了予定時刻 | 並びが変わるだけで合計は変わらない。セクション別の時間合計（F-110）は移動後のセクションで再計算される |
| sort_order | 移動先での採番は間隔採番の規則に従う（データモデル定義書 §3.5・§4.4） |

### 4.3 セクション選択の「現在のセクションへ」（O-5 / F-112）

セクション名の一覧だけでは、いま自分がどの時間帯にいるかを頭で照合してから選ぶ必要がある。それを1手で済ませるための固定候補。

| 項目 | 仕様 |
|---|---|
| 位置 | 候補一覧の**先頭に固定**し、区切り線で実セクション候補と分ける。表記は `現在のセクションへ（〈セクション名〉）` で、どこへ入るかを名前で示す |
| 「現在」の定義 | **現在時刻を含むセクション**（時刻だけで決まる）。有効セクションは24時間を敷き詰めるので必ず一意に定まる（データモデル定義書 §3.1）。§4.2 の「現在位置」（実行中タスクがあればそのセクション）とは**あえて揃えない**——利用者が知りたいのは「いまの時間帯」であり、実行中タスクが時間帯をすぎている場合に時刻とずれるため |
| 実セクション候補との重複 | 同じセクションが下の一覧にも並ぶが、**印は付けない**（先頭項目が担う）。どちらを選んでも結果は同じ |
| 挿入位置 | **移動先セクションの末尾**（通常の候補を選んだときと同じ。O-5 の規則を候補によって変えない） |
| 表示日が今日でないとき | **この候補を出さない**（現在時刻起点の値は別の日に当てても意味をなさない。終了予定 F-104・セクション残り時間 F-110・予想開始時刻 F-120 と同じ規律） |
| キーボード | 実セクション候補と同列に `J`/`K` で移動でき、`S` を押した直後は**この先頭項目を初期ハイライトにしない**（現在値のハイライトは従来どおり。F-112） |
| `Shift+J/K`（O-6）との役割分担 | O-6 は表示上の1段ずつの並べ替え、`S` は割り当て先の直接指定。「いまの時間帯へ一息で持ってくる」のは後者が担う |

## 5. 行選択モデル（キーボード操作の基盤）

- リスト上に常に「選択行」が1つ存在する（初期値: 実行中タスク、なければ最初の未実行タスク）
- `J/K` で選択行を移動（矢印キーは割り当てない。§6 / [共通](./00_共通.md) §2.1）。各ショートカットは選択行に作用する
- **並び替え（`Shift+J/K`, O-6）は移動したタスクを選択したまま追従させる**（続けて `Shift+J` すれば同じタスクを連続で下げられる）。まだ一度も明示選択していない状態で並び替えたときも、対象（現在地）を選択として確定してから移動タスクに固定する（FB-50。怠った場合の壊れ方は決定ログ）
- `C`（Current）でいつでも選択行を「現在地」へ戻せる（実行中タスク、なければ最初の未実行タスク。**初期選択と同じ規則**）。下方のプラン作業や過去日閲覧から打刻ループへ復帰する用途
- **終了打刻（実行中→完了）でタスクを完了したら、選択行を自動で「現在地」へ送る**（`C` と同じ規則。完了直後は実行中がいないため表示順で最初の未実行タスクになる）。1件ごとに選び直さず上から順にこなす打刻ループを保つ（F-211）。対象は**終了打刻のみ**（✔ ボタン・`Enter` の両方）で、完了タスクへの複製して開始（O-14 / F-208）は複製タスクへ選択が移る（O-11 と同じ）。**送り先の未実行タスクがなければ選択は完了行に据え置く**。**サーバが終了打刻を拒んだら、行の巻き戻しに合わせて選択も元の行へ戻す**（[共通](./00_共通.md) §4 / N-01。完了していない以上、選択だけ先へ送らない）
- マウス操作とキーボード操作は等価（クリックで選択も移動する）
- **選択行が画面外にあるときはスクロールを追従させ、常に見える状態を保つ**。`J/K` での移動・`C` でのジャンプ・複製（O-11）後の選択移動・**終了打刻後の選択送り（F-211）**に加え、**自動セクション移動（§4.2）で選択行の位置が変わったときも追従する**。追従は「見えていないときだけ最小限スクロールする」（既に見えているなら動かさない）

## 6. キーボードショートカット一覧

変更する場合は本表を先に更新する。共通規約は[共通](./00_共通.md) §3。

| キー | 操作 |
|---|---|
| `J` / `K` | 選択行の移動（vim に合わせる。矢印キーは割り当てない） |
| `C` | 現在地へジャンプ（実行中タスク、なければ最初の未実行タスク。Current） |
| `Enter` | 選択タスクの打刻。未実行=開始 / 実行中=終了 のトグル。**完了タスクは複製して開始**（O-14 / F-208） |
| `I` | 中断（実行中タスクのみ） |
| `A` | クイック追加欄へフォーカス（Add。Enter で追加すると追加行を選択、Esc でリストへ戻る） |
| `R` または `F2` | タスク名編集（Rename） |
| `E` | 見積もり編集（Estimate） |
| `B` / `F` | 開始時刻 / 終了時刻のインライン修正（Begin / Finish）。**打刻済みの時刻にだけ効く**（`B` は開始済みの行、`F` は完了した行。§3.3）。それ以外の行では何も起きない |
| `M` | モード選択ポップオーバー |
| `P` | プロジェクト選択ポップオーバー |
| `S` | セクション選択ポップオーバー（Section） |
| `Shift+J` / `Shift+K` | タスクの並び替え（下へ / 上へ） |
| `Y` | 選択タスクの複製（未実施のトップに挿入。vim の Yank） |
| `D` | 削除 |
| `U` | 取り消し（Undo）。**取り消しの保留（削除 O-8 / 完了の取り消し O-15）があればそれを優先**。保留がなく実行中タスクを選択中は開始打刻を取り消して未実行へ（O-13 / F-210）、完了タスクを選択中は完了を取り消して未実行へ（O-15 / F-212）。切り分けの全体は O-13 が正 |
| `Shift+H` / `Shift+L` / `T` | 前日 / 翌日 / 今日へ移動 |
| `G` | 日付を選んでジャンプ（datepicker を開く。Go to date。§3.1） |
| `?` | ショートカット一覧の表示・非表示（トグル） |

- 修飾キー・IME・テキスト入力中の扱い、**ボタンにフォーカスがある間の `Enter`（打刻しない）** など共通規約は[共通](./00_共通.md) §3 が正
- **先送り（O-7）とルーチン化（O-12）にはショートカットを割り当てない**（誤操作で実行されると後片付けが要る操作のため。行メニューから実行する）
- **`?` のヘルプ一覧には各キーのニーモニック由来を併記する**（本表の括弧書き（Add / Rename / Estimate / Begin / Finish / Current / Section / Yank / Undo / Go to date）と対応させる）
- 選択移動が `J/K`、その Shift 版が並び替え、`Shift+H/L` が日付（左右）移動、と vim の HJKL 体系で統一する
- **選択ポップオーバー（`M`/`P`/`S`）表示中は `J`/`K` で候補移動・Enter で確定・Esc で取消**（F-112）。開くと現在値をハイライトする。表示中は同じ `J`/`K` 等が背後の行操作へ流れないようにする（矢印キーは行選択同様に割り当てない）
- **datepicker（`G`）表示中は 矢印/`H`/`J`/`K`/`L` で日移動・`Enter` で確定・`Esc` で閉じる**（§3.1）。カレンダーは2次元グリッドのため、ここでは例外的に矢印キーも受け付ける。表示中は背後の行操作へ流さない
- コメント編集（F-206, Could）には `Shift+C` を予約しておく（`C` は現在地ジャンプに使用）
- 完了済みタスクを選択中の `Enter` は**複製して開始**（O-14 / F-208）。`Y`（複製）→ `Enter`（開始）でも同じことができる（`Y` は状態不問の複製）。完了タスクの打刻ボタン（✔）は操作なしのまま

## 7. 表示・性能要件

| 項目 | 仕様 |
|---|---|
| データ取得 | 表示日1日分のタスク＋マスタのみ取得（N-01, N-08）。日付移動時に隣接日をプリフェッチ |
| 打刻できる日付 | **表示日によらず打刻できる**（深夜作業で前日のタスクを開始・終了する運用を許容する）。打刻される時刻は常に実時刻であり、ずれは F-203 の時刻修正で直す |
| ルーチン展開 | 日付リクエスト時にサーバで実行（冪等）。要件定義書 §5.3 |
| タイマー表示 | 経過時間・終了予定はクライアント計算。打刻時刻はサーバ時刻ではなく**クライアントの現在時刻**を送信（オフライン考慮不要のため単純化） |
| 空状態 | タスク0件の日でもセクション見出しは表示する。タスクが1件もない旨はクイック追加欄の案内で示す |

ポップオーバー（O-5 の M/P/S・行メニュー・ルーチン化）の表示位置と閉じ方は[共通](./00_共通.md) §2.1 が正。

## 8. バリデーション・エラー

トーストの表示時間・閉じ方は[共通](./00_共通.md) §2.2 が正。

| ケース | 挙動 |
|---|---|
| 開始 > 終了 となる時刻修正 | インラインでエラー表示し確定不可 |
| 見積もりに非数値/負値 | 確定不可 |
| クイック追加欄が空（または空白のみ）で Enter | 何もしない（タスクは作られない） |
| 永続化失敗（ネットワーク等） | トースト「保存に失敗しました」＋UIロールバック。リトライは手動 |
| 別PCとの同時操作の競合 | 楽観的更新の後勝ちを許容する（同時に触る運用は想定しない）。実害が出たら再検討 |
| 日をまたぐ実行中タスク（就寝タスク等） | ended_at は実時刻で記録し、タスクは開始日（task_date）に属したまま。翌日リストには表示しない |
| 実行中タスクが前日以前に放置されている（F-209） | 当日リスト上部に警告バナー「前日以前の実行中タスクがあります」を表示し、該当日へのリンクを置く（終了打刻の失念対策）。判定は「表示日より前」 |
