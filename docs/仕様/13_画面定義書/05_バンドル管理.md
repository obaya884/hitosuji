## 1. 画面の役割

バンドル（関連ルーチンの束ね。F-119）の一覧・作成・編集と、**メンバーの出し入れ**を行う。バンドルを基準にメンバーを一望し、運用ルール（メンバーの開始想定時刻をバンドル順に昇順で付ける・同じ繰り返しのルーチンだけを入れる。要件定義書 §5.6）を保つための場。ルーチンを基準に探す S-02 では、バンドル単位で見直すのに手間がかかるため画面を分ける。

利用頻度は低い（ルーチンの見直しと同じ週1回程度）ため、S-01 ほどの操作最適化は行わない。**この画面は N-01（楽観的更新）の対象外**とし、保存の完了を待って一覧へ反映する（即UI反映＋ロールバックは行わない）。したがってこの画面の更新はすべて「確定を待つ操作」であり、進行中の合図と再発火の抑止が掛かる（[00_共通](./00_共通.md) §4.2）。

**この画面で直せるのはメンバーシップだけ**とする（出し入れ）。ルーチンの値——名前・見積もり・繰り返し・開始想定時刻・モード・プロジェクト——の編集はすべて S-02 が持ち、メンバー名のクリックでそちらへ渡す。**同じ編集手段を2画面に置かない**——検証・文言・保存の挙動を二重に保つことになり、片方だけ直る事故が起きる。この画面の役目は「**バンドル基準で見比べて、入れる・外すを決める**」ことに絞る。

## 2. レイアウト

```
┌────────┬─────────────────────────────────────────────────────┐
│ Hitosuji│ バンドル                                             │ ← 画面見出し(h1)
│        │─────────────┬───────────────────────────────────────│
│ デイリー │ ■ 朝の立上げ 4│ ■ 朝の立上げ    [名前・色を編集][アーカイブ]│
│ ルーチン │ ■ 集中ブロック2│ 名前     モード 繰り返し 見積 開始想定    │
│ バンドル │ ■ 週末の整理 3│ 朝食     生活   毎日     0:20 06:30 外す │
│ マスタ  │              │ 洗面     生活   毎日     0:05 06:50 外す │
│ レビュー │              │ 日次プラン 計画 毎日     0:15 07:00 外す │
│        │ [＋ 新規追加] │ 週次レビュー 仕事 週次(土) 0:30 07:20 外す│
│        │ ▸ アーカイブ済み│ [＋ ルーチンを追加 ▾]                  │
└────────┴─────────────┴───────────────────────────────────────┘
```

- 画面見出し（h1）「バンドル」を置く（[共通](./00_共通.md) §1）
- **左に一覧・右に選択中バンドルのメンバー表**の2ペイン。左ペインは幅を固定し、右ペインが残りを使う。**左ペインの幅は「新規追加行（色見本＋名前の入力欄＋保存／取消）が折り返さずに収まること」で決まる**——狭めると入力欄が境界を越えて崩れる
- **見出し行には「＋ 新規追加」だけを置き、説明文は書かない**。他の管理画面（[02](./02_ルーチン管理.md)・[03](./03_マスタ管理.md)）が持つ説明文に相当することが、この画面では操作すれば分かることしか無いため（利用者はオーナー1人で、バンドルが何かの説明も要らない）
- 装飾のないテーブル型リスト（N-05）。文字サイズは[共通](./00_共通.md) §1.1 の3段スケールに従う

## 3. 表示要素

### 3.1 バンドル一覧（左ペイン）

| 要素 | 仕様 |
|---|---|
| 色 | バンドル色（`bundles.color`）の小さな四角。デイリーの縦帯（[01](./01_デイリーリスト.md) §3.3）と同じ色なので、道とバンドル名の対応がここでつく |
| 名前 | テキスト。**選択中の行は地色を `accent-weak` にする**（選択行の表し方はデイリーと同じ） |
| 選択の当たり判定 | **行全体**（色見本や件数を押しても選べる）。地色が行全体に付く以上、押せる範囲もそこに揃える。名前に下線は出さない——乗ったことは行の地色が示す |
| メンバー件数 | 名前の右端に件数だけを出す。**0件のバンドルも `0` を出す**（値が確定しているので[共通](./00_共通.md) §2.4 の薄色表記は使わない） |
| 並び順 | name の自然順（マスタ共通。データモデル定義書 §1）。手動の並び替えは提供しない |
| アーカイブ済み | 一覧下部に折りたたみ表示し、展開すると復元・削除ができる（[03](./03_マスタ管理.md) §4「アーカイブ」と同じ扱い） |
| 初期選択 | 画面を開いたときは**有効なバンドルの先頭**を選ぶ。1件もなければ右ペインは空状態（下記） |

### 3.2 メンバー表（右ペイン）

ヘッダに選択中バンドルの色・名前と、名前・色の編集（O-2）とアーカイブ（O-3）の導線を置く。

| 列 | 仕様 |
|---|---|
| 名前 | ルーチン名。**クリックで S-02 へ渡す**（O-7）。無効ルーチン（`is_active = false`）は行をグレーアウトする（S-02 §3 と同じ扱い。無効なメンバーは展開されず道が欠けるため、区別が要る） |
| モード | モード名。未設定の表記は[共通](./00_共通.md) §2.4 |
| 繰り返し | 人間可読の要約表示（表記は [02](./02_ルーチン管理.md) §3 が正）。**揃っていないことを画面から知らせる仕組みは持たない**——列が縦に並ぶので目視で読める（[31_バンドル検討.md](../../検討/31_バンドル検討.md) §7.4 で保留） |
| 見積もり | `H:MM` |
| 開始想定時刻 | `HH:MM`。**読むだけ**（直すのは S-02。O-7）。セクション名の併記はしない（S-02 と違い、ここで読みたいのはバンドル内の前後関係のため） |
| 操作 | 「外す」（O-6） |

- **並び順は開始想定時刻の昇順**（同時刻は名前の自然順）。運用ルール「時刻をバンドル順に昇順で付ける」がそのまま並びとして見えるので、崩れていれば気づける。**並べ替えは提供しない**（軸を変えると点検の意味がなくなる）
- **メンバー0件のバンドル**: 表の代わりに「まだルーチンが入っていません」を出し、「＋ ルーチンを追加」だけを置く
- **バンドル0件**: 右ペインに「バンドルがありません」を出す

## 4. 操作仕様

| # | 操作 | 仕様 |
|---|---|---|
| O-1 | バンドルの新規作成 | 左ペイン下部の「＋ 新規追加」。名前と色を入力して作成し、**作成したバンドルを選択状態にする**（続けてメンバーを入れられる） |
| O-2 | 名前・色の編集 | 右ペインのヘッダから。名前はインライン編集、色はカラーバーを押してプリセット13色から選ぶ（**部品も候補も [03](./03_マスタ管理.md) §3.2 のモードと同じ**。色名の吹き出し・自由入力を設けない点も同じ） |
| O-3 | アーカイブ / 復元 | 右ペインのヘッダから。アーカイブすると左ペイン下部の折りたたみへ移り、**S-02 のバンドル選択の候補から外れる**（[03](./03_マスタ管理.md) §4「アーカイブ済みマスタの扱い」と同じ）。**既にメンバーになっているルーチンの所属も、展開済みタスクの道もそのまま**（過去の参照を保つ） |
| O-4 | 物理削除 | §5 |
| O-5 | メンバーの追加 | 右ペイン下部の「＋ ルーチンを追加」。**候補はどのバンドルにも属していないルーチンだけ**——他バンドル所属を出して選ばせると、そちらから黙ってメンバーが抜ける。付け替えたいときは元のバンドルで「外す」→ここで追加の2手を踏む。無効ルーチンも候補に出す（後で有効化しうるため）。候補の並びは開始想定時刻の昇順 |
| O-6 | メンバーを外す | 行の「外す」。`routines.bundle_id` を未設定に戻す。**展開済みタスクには波及しない**（既に出ている当日タスクは道に乗ったまま。データモデル定義書 §4.8） |
| O-7 | ルーチンの編集へ移る | メンバー名のクリックで S-02 へ遷移し、**そのルーチンの編集フォームを開いた状態にする**。**ルーチンの値の編集はすべてここを通る**（名前・見積もり・繰り返し・**開始想定時刻**・モード・プロジェクト）。並びを直したいときも、この導線で時刻を直せば戻ったときに組み替わっている |

- **キーボードショートカットは設けない**（S-02 / S-03 と同じ。ショートカットは S-01 に閉じる。[共通](./00_共通.md) §3）
- **完了の通知は出さず、失敗は表の上部にエラーの帯で出す**（S-02 / S-03 と同じ扱い。[共通](./00_共通.md) §4.1）。**取り消し（Undo）は提供しない**——どの操作も同じ画面で逆操作ができる（外した相手はすぐ足せる、時刻は打ち直せる）

## 5. 物理削除（F-405）

誤って作ったバンドルを片付けるための例外手段。**手順・確認・競合時の扱いは [03](./03_マスタ管理.md) §4.1 と同じ**（アーカイブ済みの行にのみ、参照0件のときだけ「削除」を出す。2段階確認・Undoなし・実行時にサーバ側で再チェック）。

| 項目 | 仕様 |
|---|---|
| 参照件数の数え方 | `routines.bundle_id` ＋ `tasks.bundle_id`。**展開済みタスクからの参照も数える**ので、一度でも道が出た日があるバンドルは削除できない（過去のログの見え方を壊さないため。アーカイブで十分） |
| 表示場所 | 左ペインの「アーカイブ済み」折りたたみの中 |

## 6. バリデーション・エラー

トーストの表示時間・閉じ方は[共通](./00_共通.md) §2.2 が正。

| ケース | 挙動 |
|---|---|
| 名前が空（または空白のみ） | 確定不可（前後の空白は落として保存する。[03](./03_マスタ管理.md) §4「名前の入力」と同じ。**文字数の上限は設けない**） |
| 繰り返しが揃っていないメンバーの追加・保存 | **妨げない**（運用ルールであってハード制約ではない。[31_バンドル検討.md](../../検討/31_バンドル検討.md) §2） |
| すでに削除されたバンドル・ルーチンへの操作 | **失敗として扱う**（1行も当たらない更新を成功として返さない。[共通](./00_共通.md) §4.1）。「対象が見つかりません（すでに削除されている可能性があります）」を表示し、一覧を取り直す |
| 追加しようとしたルーチンが別のバンドルに入っていた（別タブでの操作） | サーバ側で再チェックし、エラーを表示して追加しない（候補の絞り込み〈O-5〉を画面側だけの保証にしない） |
| 永続化失敗（通信断・サーバが返す失敗） | [共通](./00_共通.md) §4.1 が正。**表の上部にエラーの帯で出す**（S-02 / S-03 と同じ）。この画面は楽観的更新をしないのでロールバックは起きず、編集状態を残して入力し直せるようにする |
