## 1. 画面の役割

セクション・モード・プロジェクトの3マスタを管理する。タブ切替で1画面に集約する。利用頻度は低く（初期設定時と、プロジェクト追加時程度）、シンプルなCRUDに徹する。**この画面は N-01（楽観的更新）の対象外**とし、保存の完了を待って一覧へ反映する（即UI反映＋ロールバックは行わない）。したがってこの画面の更新はすべて「確定を待つ操作」であり、進行中の合図と再発火の抑止が掛かる（[00_共通](./00_共通.md) §4.2）。

## 3. タブ別仕様

### 3.1 セクション

| 列 | 仕様 |
|---|---|
| 日界 | **1日の開始（日界）セクションの選択**（F-116）。各行の先頭にラジオを置き、選択された1行が日界セクション。日界時刻＝その行の `start_time`。**現在の日界はラジオの選択状態だけで示す**（行内にラベル文字列は置かない。意味は列見出し「日界」と一覧上部の説明文が伝え、読み上げには `〜を1日の開始にする` の `aria-label` を持つ）。選択を切り替えると「今日」の解決とデイリーのセクション表示順（回転）がその起点に変わる（データモデル定義書 §3.1 / 画面定義書01 §3.1・§3.2）。**日界にできるのは有効セクションだけ**——アーカイブ済み一覧にはラジオを置かない（日界セクションはアーカイブ不可なので、逆向きも起こらない） |
| 名前 | テキスト（§4「名前の入力」） |
| 開始 | `HH:MM`。**終了時刻は入力しない**（次セクションの開始から自動導出され、`06:00–09:00` のように枠として表示のみ） |
| 長さ | その枠が何時間あるか。`H:MM`（例 `3:00` / 日をまたぐ `22:00–06:00` なら `8:00`）。値は枠の長さ（データモデル定義書 §3.1）そのもので、デイリーの「合計 2:30/3:00」の分母（F-110 / 画面定義書01 §3.2）と同じ。導出値なので編集はしない。**アーカイブ済み一覧には出さない**——枠の導出対象外で終了時刻が定まらないため（同じ理由でデイリーも残り時間を出さない。データモデル定義書 §4.3） |
| 操作 | アーカイブ（編集は §4「編集方式」のインライン編集で行う）。**日界セクションはアーカイブ不可**（ボタンを非活性にし、先に別セクションを日界へ指定させる） |

- 並び順は `start_time` 昇順で自動決定（手動の並び替えは提供しない。時刻を編集すれば並びが追従する）。**この画面の一覧は暦日 `start_time` 昇順で見せる**（デイリーの回転表示とは別。マスタ設定はどのセクションが何時開始かを一望する場が目的）
- 有効なセクションは常に24時間を隙間・重複なく敷き詰める（データモデル定義書 §3.1）。開始時刻を編集すると、自身と前のセクションの枠が連動して変わる

**バリデーション**: 有効セクション間の start_time 重複はエラー。有効なセクションは最低1件必要（全件アーカイブ不可）。日界セクションはちょうど1件（選択の切替は他行の解除を伴う。アーカイブ不可）。重複・隙間のチェックは構造上不要。

初期データはデータモデル定義書 §5 が正。

## 4. 共通仕様

| 項目 | 仕様 |
|---|---|
| 名前の入力 | 空・空白のみは確定不可（前後の空白は落として保存する）。**文字数の上限は設けない**——長い名前を入れるのはオーナー自身であり、機械が止める理由がない（データモデル定義書 §3.1〜§3.3 も同じ。ルーチン名は画面定義書02 §4）。**極端に長い名前を入れたときの一覧の見え方は規定しない**（実運用で入れないため。必要になった時点で条項を起こす） |
| 編集方式 | **値のセルをクリックするとその場が入力欄になる**（保存・取消・保存中の制約は[共通](./00_共通.md) §2.3 が正）。更新は行の全項目をまとめて送る |
| 並び順 | 手動の並び替えは提供しない。並び順の規則はデータモデル定義書 §1 が正（セクションは start_time 昇順、モード・プロジェクトは name 昇順の自然順）。並びを制御したい場合は `01.仕事` のように名前へ接頭辞を付ける運用 |
| アーカイブ | 物理削除は原則提供しない（例外は §4.1＝参照0件のみ）。アーカイブ済みは一覧下部に折りたたみ表示し、復元可能。過去タスク・ルーチンからの参照は保たれる |
| アーカイブ済みマスタの扱い | S-01/S-02 の選択肢には表示しない。参照中のタスク表示には従来どおり使われる |
| 名前変更の影響 | 参照している全タスク・ルーチンの表示に即時反映される（IDで参照しているため） |
| 削除的な整理が必要な場合 | 誤作成直後のみ想定。参照0件のマスタに限り物理削除ボタンを表示する（下記） |
| すでに削除されたマスタへの操作 | 別タブ・別端末で削除された対象への更新・アーカイブ切替・復元・日界切替は、いずれも**失敗として扱う**（1行も当たらない更新を成功として返さない。[共通](./00_共通.md) §4.1）。「対象が見つかりません（すでに削除されている可能性があります）」を表示し、一覧を取り直す |

### 4.1 物理削除（F-405）

誤って作ったマスタを片付けるための例外手段。**アーカイブ済み一覧の行にのみ**、かつ**参照0件のときだけ**「削除」ボタンを表示する（参照がある行にはボタン自体を出さない）。有効な行には表示しない — 整理は「アーカイブ → 削除」の順で行う。

| 項目 | 仕様 |
|---|---|
| 参照件数の数え方 | セクション: `tasks.section_id` / モード: `tasks.mode_id` ＋ `routines.mode_id` / プロジェクト: `tasks.project_id` ＋ `routines.project_id`。ルーチンはセクションを参照しない（開始想定時刻から導出するため） |
| 確認 | モーダルは使わない。「削除」を押すと同じ位置が「本当に削除？ [削除する] [取消]」に切り替わる2段階。実行後の Undo は提供しない |
| 有効セクション最低1件 | アーカイブ済みのみが対象のため、この制約に抵触することはない |
| 競合時 | ボタン表示後に参照が生まれた場合（別タブでの操作など）はサーバ側で再チェックし、エラーメッセージを表示して削除しない |
