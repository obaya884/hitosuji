# 画面定義書 S-00: 全画面共通

- 版数: 1.0
- 更新日: 2026-07-26
- 対応要求: N-01（体感即応）, N-04（キーボード操作）, N-05（シンプルなUI）, N-11（操作結果の通知）
- 上位文書: [要件定義書](../12_要件定義書.md)

全画面に共通する枠組み・UI部品・作法を定める。各画面定義書（01〜04）はここを参照し、同じ内容を再掲しない。

---

## 1. 全体レイアウト

```
┌────────┬─────────────────────────────────────────────┐
│Hitosuji│ 画面見出し(h1)                              │
│        │                                             │
│ デイリー │ 本文（中央寄せ・最大幅）                     │
│ ルーチン │                                             │
│ マスタ  │                                             │
│ レビュー │                                             │
└────────┴─────────────────────────────────────────────┘
  ↑ Navigation Rail（画面に固定）
```

| 項目 | 仕様 |
|---|---|
| アプリ名（Hitosuji） | レール上部に置く。クリックで今日のデイリー（日付パラメータなしのルート `/`）へ遷移する（ロゴ＝ホーム。FB-45） |
| Navigation Rail | 左サイドに縦並び。項目は デイリー / ルーチン / マスタ / レビュー。**ラベルのみでアイコンは使わない**。現在地はレールの項目に表示する |
| レールの固定 | 画面に固定し、本文をスクロールしても常に見える |
| 本文 | 中央寄せ・最大幅。レール導入後も幅は変えない |
| 画面見出し（h1） | 各画面の本文先頭に置く（S-01「デイリー」/ S-02「ルーチン」/ S-03「マスタ管理」/ S-04「レビュー」）。レールに現在地があっても本文側にも示す |
| ログイン画面 | 設けない（Basic認証はブラウザ標準ダイアログ） |

## 2. 共通UI部品

### 2.1 ポップオーバー

モーダルは最小限とし、選択・入力はその場に開くポップオーバーで行う（N-05）。

| 項目 | 仕様 |
|---|---|
| 閉じ方 | `Esc` キーと、外側のクリック |
| 表示位置 | 既定は起点の**下**に開く。**下に入りきらず、かつ上の余白の方が広いときだけ上向きに反転する**。位置は開いた直後に1回だけ決め、開いている間はスクロールしても動かさない |
| 候補選択 | クリック、または `J`/`K` で候補移動して Enter で確定・Esc で取消（開くと現在値をハイライト）。矢印キーは使わない（FB-33）。詳細は S-01 §6（F-112） |
| 候補の折り返し | **候補は1行に収め、折り返さない**（行高が候補ごとに変わると `J`/`K` の移動が読みにくくなる）。幅に収まらない名前は**末尾を省略する**。名前の右への付記（セクションの時間帯 S-01 O-5 等）は省略せず、名前側を詰める |
| 文字色 | 通常色（`text-ink`）。行内に開く場合でも行のモード色（F-401）は継承しない（FB-38） |

### 2.2 トースト（N-11）

操作の結果は画面を止めずにトーストで知らせる。確認が要る破壊的操作（打刻済みタスクの削除・マスタの物理削除）だけは事前確認を挟む。

| 項目 | 仕様 |
|---|---|
| 用途 | 操作の取り消し（Undo。F-115）・完了通知・エラー通知 |
| 消え方 | **すべて自動で消え、閉じるボタン（×）でも消せる** |
| 表示時間 | Undo 付き・完了通知は5秒 / エラーは8秒（エラーは読む時間が要るため長く取る） |
| 位置 | 画面下部中央。複数出る場合も重ならないよう1箇所に積む |
| 取り消しの期限 | **Undo が有効なのはそのトーストが出ているあいだだけ**。自動消去・× のどちらで消えても保留は破棄され、以後はボタンでもキーでも取り消せない（保留を無期限に持つと、何を戻す操作なのかが読めなくなるため） |

### 2.3 インライン編集

一覧の値はセルをクリックしてその場で編集する（編集ボタンを都度押さない）。

| 項目 | 仕様 |
|---|---|
| 確定 | `Enter` または入力欄からフォーカスが外れたとき |
| 取消 | `Esc`（元の値に戻す） |
| 変更なしの確定 | 何も送信せず閉じる |
| 保存中 | **同じ行の編集・確定・取消をすべて止める**——他のセルも、同じセルの開き直しも、**開いたままの入力欄からの再確定も**（応答を待つ間に値を変えて確定すると2件目の更新が飛ぶ）。目的は古い値での上書きと二重送信を防ぐことなので、**行内に編集可能なセルが1つしかない場合も同様に止める**。**適用は保存完了を待って反映する画面に限る**——楽観的更新（N-01）の画面では別セルを開いた時点で画面の値がすでに新しく、この条項が防ぐ事故が起きない |
| 新規追加行・新規作成フォームの保存中 | 同じく**確定（`Enter`・保存ボタン）と取消をどちらも止める**。`Enter` を連打すると同じものが二重に作られ、応答を待つ間に取消すと入力が閉じて失敗のメッセージだけが残る。**インライン編集のセルに限らず、保存完了を待って反映する画面の作成フォームにも及ぶ**（ルーチン管理の新規作成フォーム） |
| 保存中に始める操作 | **新しい編集を始める操作も止める**（一覧の「新規追加」ボタン等）——押すと編集中のセルが閉じてしまい、失敗が返っても入力し直せない＝実質的に上の「取消」と同じ。**送信せず表示だけを変えるその場の選択**（モードの色の選択など）も同様に止める。保存中だけ送信する値と画面の表示が食い違うため |
| 失敗時 | 編集状態のまま残し、入力し直せるようにする |

### 2.4 未設定の表記

値が入っていないことの示し方を全画面で揃える。**空欄にはしない**——空欄は「そこに表示する余地がない」と読めてしまい、クリックして設定できることが伝わらないため。

| 対象 | 表記 |
|---|---|
| 属性（モード・プロジェクト等、マスタを参照する値） | **薄色の `-`**。マスタの名前をプレースホルダとして出さない（「モード」「プロジェクト」という語を並べると、未設定行の多い列が同じ語で埋まって視線のノイズになる） |
| 時間の値（見積もり・実績・打刻時刻） | **薄色の `--:--`**。`-` と使い分けるのは、時間には「未設定（0分）」と「未確定（実行中で実績が出ていない）」の2種があり、桁の形を保ったまま不在を示す必要があるため。`1分未満の実績` のように値が確定しているものは `0:00` で、`--:--` は使わない |
| 集計の「未設定」グループ | 上記とは別。セルの不在ではなく行のラベルなので「（未設定）」と書く（S-04 §3.5） |

## 3. キーボード操作の共通規約

- **修飾キーは Shift のみ使用**し、ブラウザ既定動作の抑止（`preventDefault`）を最小化する。`Cmd/Ctrl` 系・`Space`（ページスクロール）は使わない
- **IME変換中のキーは操作として扱わない**。日本語入力の変換確定 `Enter` が保存・確定として発火しないよう、`isComposing` 中の `Enter` / `Escape` は無視する
- テキスト入力中は画面のショートカットを無効にする（`Esc` で入力を抜けてから有効化）
- **ボタンにフォーカスがある間の `Enter` は画面のショートカットとして扱わない**。ブラウザがそのボタンを押すため、ショートカットも走ると同じ操作が二重に発火する（打刻ボタンを押した直後の `Enter` など）
- 画面固有のショートカットは各画面定義書が定める（S-01 は §6）

**上4条のかかり方**: 箇条1・2（修飾キー・IME）は**キー操作すべて**にかかる。箇条3・4 は文中のとおり**画面全体のショートカット**にかかり、ポップオーバーや日付ピッカーのような**オーバーレイが開いている間、その内側で処理するキー**（`Esc` で閉じる・矢印で候補を移動する等）は対象外——開いている間はオーバーレイが入力の主体で、背後の画面のショートカットは別途止まっているため。コード側もこの区切りに合わせて判定を2本に分けている（`isOperableKeyEvent` = 箇条1・2 のみ／`isGlobalShortcutEvent` = 箇条1〜4）。

## 4. 更新の作法

- 更新操作は原則として**楽観的更新**（即UIに反映 → 非同期で永続化、失敗時はトースト＋ロールバック）。適用範囲と対象外は要件定義書 §6 N-01 が正
- 永続化に失敗したときのメッセージは「保存に失敗しました」。リトライは手動
