# 画面定義書 S-00: 全画面共通

- 版数: 1.0
- 更新日: 2026-08-08
- 対応要求: N-01（体感即応）, N-04（キーボード操作）, N-05（シンプルなUI）, N-11（操作結果の通知）
- 上位文書: [要件定義書](../12_要件定義書.md)

全画面に共通する枠組み・UI部品・作法を定める。各画面定義書（01〜04）はここを参照し、同じ内容を再掲しない。

---

## 1. 全体レイアウト

```
┌────────┬─────────────────────────────────────────────┐
│Hitosuji│ 画面見出し(h1)                              │
│        │                                             │
│ デイリー │ 本文（中央寄せ・最大幅）                     │
│ ルーチン │                                             │
│ マスタ  │                                             │
│ レビュー │                                             │
└────────┴─────────────────────────────────────────────┘
  ↑ Navigation Rail（画面に固定）
```

| 項目 | 仕様 |
|---|---|
| アプリ名（Hitosuji） | レール上部に置く。クリックで今日のデイリー（日付パラメータなしのルート `/`）へ遷移する（ロゴ＝ホーム。FB-45） |
| Navigation Rail | 左サイドに縦並び。項目は デイリー / ルーチン / マスタ / レビュー。**ラベルのみでアイコンは使わない**。現在地はレールの項目に表示する |
| レールの固定 | 画面に固定し、本文をスクロールしても常に見える |
| 本文 | 中央寄せ・最大幅。レール導入後も幅は変えない |
| 本文の文字サイズ | 全画面で共通の3段スケール（主 / 従 / メタ）に従う（§1.1） |
| 画面見出し（h1） | 各画面の本文先頭に置く（S-01「デイリー」/ S-02「ルーチン」/ S-03「マスタ管理」/ S-04「レビュー」）。レールに現在地があっても本文側にも示す |
| ログイン画面 | 設けない（Basic認証はブラウザ標準ダイアログ） |

### 1.1 文字サイズ

**全画面で同じ3段のスケールを使う**。段はサイズだけで表し、**主従を色で表さない**（文字色はモード色 F-401 が使うため、色に主従を持たせると行ごとに見え方が変わる）。

| 段 | 何が入るか | サイズ |
|---|---|---|
| **主** | 行の**名前**（タスク名・ルーチン名・マスタの名前）と、**時間の値すべて**（見積・実績・差異・実施時間・開始想定時刻・セクションの時間帯と長さ）。画面上部のサマリの数値もここ | 大 |
| **従**（既定） | **分類**（モード・プロジェクト・繰り返し・モードの色名）、コメント、列見出し行、フォームの入力欄とその行、節見出し（h2）、空状態のメッセージ、本文に併記する従の情報（タスク名に添えるセクション名・サマリの「終了予定」等のラベル）、セクション見出し行の見出し語 | 中 |
| **メタ** | 従に添える補足。セクション見出し行の時間帯・合計・残り・進捗、フォームの項目ラベルと注記 | 小 |

- 主と従の境界は「**時間の値か、それ以外か**」。このアプリが読ませたいのは時間なので、時刻・所要時間はいずれも主に置く（記録か予定かで分けない）
- 1行の中で主は複数あってよい（名前と時間が同居する）。**分類を主へ上げない**ことがこの段の要点
- 段は**その行での役割**で決める。モード名・プロジェクト名でも、それが行の見出しになっている表（レビューの集計 [04](./04_レビュー.md) §3.5）では「名前」＝主。分類が従なのは、名前を持つ行にその属性として添えられている場合
- **対象外**: ボタン・浮遊面（ポップオーバー・モーダル・トースト）・ナビゲーション。これらは本文の一部ではなく部品なので、部品側の規約に従う。ただし**対象外の部品は自分のサイズを自分で持つ**——本文から継承させると、置かれた場所の段によって同じ部品の大小が変わる（行の操作列のリンクが主と同じ大きさになる、など）

## 2. 共通UI部品

### 2.1 ポップオーバー

モーダルは最小限とし、選択・入力はその場に開くポップオーバーで行う（N-05）。

**適用範囲**: 「全画面」の項目はどの画面のポップオーバーにも及ぶ。それ以外の項目は**デイリーリスト（S-01）向けの規約**で、他画面のポップオーバーには及ばない（マスタ管理のカラーピッカー §3.2 等）。S-01 のどのポップオーバーが対象かは項目ごとに異なるため、「適用」列に明記する。

| 項目 | 適用 | 仕様 |
|---|---|---|
| 閉じ方 | 全画面 | `Esc` キーと、外側のクリック |
| 表示位置 | S-01 のポップオーバー全般（属性選択 O-5・行メニュー・ルーチン化・日付ピッカー） | 既定は起点の**下**に開く。**下に入りきらず、かつ上の余白の方が広いときだけ上向きに反転する**。位置は開いた直後に1回だけ決め、開いている間はスクロールしても動かさない |
| 候補選択 | S-01 の候補選択ポップオーバー（属性選択 O-5。F-112 / N-04） | クリック、または `J`/`K` で候補移動して Enter で確定・Esc で取消（開くと現在値をハイライト）。矢印キーは使わない（FB-33）。詳細は S-01 §6（F-112）。日付ピッカーは候補一覧ではなく月グリッドのため、この規約に準じた独自のキー割当を持つ（S-01 §3.2） |
| 候補の折り返し | S-01 の候補選択ポップオーバー（属性選択 O-5） | **候補は1行に収め、折り返さない**（行高が候補ごとに変わると `J`/`K` の移動が読みにくくなる）。幅に収まらない名前は**末尾を省略する**。名前の右への付記（セクションの時間帯 S-01 O-5 等）は省略せず、名前側を詰める |
| 文字色 | 全画面 | 通常色（`text-ink`）。行内に開く場合でも行のモード色（F-401）は継承しない（FB-38） |

### 2.2 トースト（N-11）

操作の結果は画面を止めずにトーストで知らせる。確認が要る破壊的操作（打刻済みタスクの削除・マスタの物理削除）だけは事前確認を挟む。

| 項目 | 仕様 |
|---|---|
| 用途 | 操作の取り消し（Undo。F-115）・完了通知・エラー通知 |
| 消え方 | **すべて自動で消え、閉じるボタン（×）でも消せる** |
| 表示時間 | Undo 付き・完了通知は5秒 / エラーは8秒（エラーは読む時間が要るため長く取る） |
| 位置 | 画面下部中央。複数出る場合も重ならないよう1箇所に積む |
| 取り消しの期限 | **Undo が有効なのはそのトーストが出ているあいだだけ**。自動消去・× のどちらで消えても保留は破棄され、以後はボタンでもキーでも取り消せない（保留を無期限に持つと、何を戻す操作なのかが読めなくなるため） |

### 2.3 インライン編集

一覧の値はセルをクリックしてその場で編集する（編集ボタンを都度押さない）。

| 項目 | 仕様 |
|---|---|
| 確定 | `Enter` または入力欄からフォーカスが外れたとき |
| 取消 | `Esc`（元の値に戻す） |
| 変更なしの確定 | 何も送信せず閉じる |
| 保存中 | **同じ行の編集・確定・取消をすべて止める**——他のセルも、同じセルの開き直しも、**開いたままの入力欄からの再確定も**。目的は古い値での上書きと二重送信の防止で、**行内に編集可能なセルが1つしかない場合も同様に止める**。**適用は保存完了を待って反映する画面に限る**——楽観的更新（N-01）の画面では別セルを開いた時点で画面の値がすでに新しく、この条項が防ぐ事故が起きない |
| 新規追加行・新規作成フォームの保存中 | 同じく**確定（`Enter`・保存ボタン）と取消をどちらも止める**。**インライン編集のセルに限らず、保存完了を待って反映する画面の作成フォームにも及ぶ**（ルーチン管理の新規作成フォーム。各条の事故例は決定ログ） |
| 保存中に始める操作 | **新しい編集を始める操作も止める**（一覧の「新規追加」ボタン等）。**送信せず表示だけを変えるその場の選択**（モードの色の選択など）も同様に止める |
| 失敗時 | 編集状態のまま残し、入力し直せるようにする |

### 2.4 未設定の表記

値が入っていないことの示し方を全画面で揃える。

**「空欄にしない」が掛かるのは、クリックしてその場で値を入れられるセル**（属性・見積もり）。空欄をやめる理由は、空欄が「そこに表示する余地がない」と読めて**クリックして設定できることが伝わらない**ためで、**設定できないセル——打刻の結果として決まる実績・打刻時刻、そこから導出される差異——には掛からない**。そちらは値が無いあいだ空欄でよく、記号を出すかどうかは各画面定義書が決める。

**記号で示すのは一覧のセルだけ**で、それ以外（選択肢・読み上げ・集計の行ラベル）は語で示す。**語は「未設定」1つに揃える**——「なし」「〈属性名〉なし」を使わない。

| 対象 | 表記 |
|---|---|
| 設定できるセル: 属性（モード・プロジェクト等、マスタを参照する値） | **薄色の `-`**。マスタの名前をプレースホルダとして出さない（「モード」「プロジェクト」という語を並べると、未設定行の多い列が同じ語で埋まって視線のノイズになる） |
| 設定できるセル: 時間の値（見積もり） | **薄色の `--:--`**。`-` と使い分けるのは、桁の形を保ったまま不在を示す必要があるため。値が確定しているもの（1分未満の実績）は `0:00` で、`--:--` は使わない |
| 記録・導出のセル: 時間の値（実績・打刻時刻・差異） | 値が無いあいだは**空欄でよい**。ただし**桁の形で「未確定」を示したい場合は `--:--` を使う**（レビューの実行中行 S-04 §3.3）。どちらにするかは各画面定義書が決める |
| `--:--` の色 | **出すところでは必ず薄色にする**——セルか見出しの補足か、設定できるセルか記録のセルかによらない（セクション見出しの時間合計 S-01 §3.2 のようにメタ段の中でも、そこからさらに薄くする）。同じ記号が場所によって濃さの違う表示になると、色の差を意味の差と読んでしまうため |
| 属性を未設定に戻す選択肢（ポップオーバーの候補・フォームのセレクト） | **「未設定」**。属性名を冠さない——何の属性かは開いた列・項目ラベルが示しており、冠すると候補で語が長くなるうえフォームでは直上のラベルと重複する。**ポップオーバーの候補では薄色にする**（実マスタの名前と見分けるため） |
| セルの読み上げ（`aria-label`） | **「〈項目名〉（未設定）」**（例: `モード（未設定）`）。記号 `-` は読み上げに向かないため語を当てる |
| 集計の「未設定」グループ | **「（未設定）」**。語は上と同じで、括弧は「マスタの名前ではなく行のラベル」を示す記法（S-04 §3.5） |
| 対象外: セクションの `null` | **「未分類」**のまま。値の不在ではなく、0件でも常に表示するインボックスグループの**名前**なので、この規定の対象にしない（S-01 §3.2） |

上の語彙は実装側でも1か所（`src/app/_lib/unset.ts`）に持ち、**直書きは `eslint.config.mjs` の `no-restricted-syntax` で機械的に禁止している**（依存方向ルールと同じ流儀。[アーキテクチャ定義書](../15_アーキテクチャ定義書.md) §3）。本表を変えるときは実装側の定数も動かす。

## 3. キーボード操作の共通規約

- **修飾キーは Shift のみ使用**し、ブラウザ既定動作の抑止（`preventDefault`）を最小化する。`Cmd/Ctrl` 系・`Space`（ページスクロール）は使わない
- **IME変換中のキーは操作として扱わない**。日本語入力の変換確定 `Enter` が保存・確定として発火しないよう、`isComposing` 中の `Enter` / `Escape` は無視する
- テキスト入力中は画面のショートカットを無効にする（`Esc` で入力を抜けてから有効化）
- **ボタンにフォーカスがある間の `Enter` は画面のショートカットとして扱わない**。ブラウザがそのボタンを押すため、ショートカットも走ると同じ操作が二重に発火する（打刻ボタンを押した直後の `Enter` など）
- 画面固有のショートカットは各画面定義書が定める（S-01 は §6）

**上4条のかかり方**: 箇条1・2（修飾キー・IME）は**キー操作すべて**にかかる。箇条3・4 は文中のとおり**画面全体のショートカット**にかかり、ポップオーバーや日付ピッカーのような**オーバーレイが開いている間、その内側で処理するキー**（`Esc` で閉じる・矢印で候補を移動する等）は対象外——開いている間はオーバーレイが入力の主体で、背後の画面のショートカットは別途止まっているため。

## 4. 更新の作法

- 更新操作は原則として**楽観的更新**（即UIに反映 → 非同期で永続化、失敗時はトースト＋ロールバック）。適用範囲と対象外は要件定義書 §6 N-01 が正

### 4.1 永続化の失敗

**失敗はすべて画面に出す**——結果を捨てて成功として振る舞わない。知らせ方はトースト（§2.2 のエラー通知）で、リトライは手動。失敗は結果が届いたかどうかで2種に分かれ、メッセージと画面の直し方が変わる。

| 種別 | 起きること | メッセージ | 画面の直し方 |
|---|---|---|---|
| 結果が届かなかった | 通信断・タイムアウト・サーバ側の異常終了 | 「保存に失敗しました」 | ロールバックのみ。**サーバへ取り直しに行かない**（届かない以上また失敗するため） |
| サーバが失敗を返した | 対象がすでに存在しない、状態が操作の前提と違う 等 | その失敗に応じた文言（例「タスクが見つかりませんでした」） | ロールバックに加え、**表示中のデータをサーバから取り直す**。消えた行が画面に残り、触るたび同じ失敗を繰り返す状態にしない |

- **すでに存在しない対象への更新は、サーバが失敗として返す**（他の画面・端末で削除された場合など）。更新が1行も当たらなかったことを成功として返し、画面だけ変わった状態にしない
- ロールバックがあるのは楽観的更新の画面（S-01）だけ。保存完了を待って反映する画面（S-02 / S-03）は画面がまだ変わっていないため、編集状態を残して入力し直せるようにする（§2.3 失敗時）
