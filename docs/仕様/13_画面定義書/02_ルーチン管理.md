## 1. 画面の役割

ルーチン（デイリーリストへ自動展開されるタスクの雛形）の一覧・作成・編集・有効/無効切替を行う。利用頻度は低い（週1回程度の見直し）ため、S-01ほどの操作最適化は行わずシンプルなCRUDに徹する。**この画面は N-01（楽観的更新）の対象外**とし、保存の完了を待って一覧へ反映する（即UI反映＋ロールバックは行わない）。したがってこの画面の更新はすべて「確定を待つ操作」であり、進行中の合図と再発火の抑止が掛かる（[00_共通](./00_共通.md) §4.2）。

## 3. 表示要素（一覧）

列は左から **名前 / プロジェクト / モード / 繰り返し / 開始想定 / 見積 / バンドル / 有効 / 操作** の順に並べる。**ルーチンを読む順に並べる**——「何を〈名前〉／どの件で〈プロジェクト〉／どういう性質か〈モード〉」まではデイリー（[01_デイリーリスト](./01_デイリーリスト.md) §3.3）と同じ並びで、そこへルーチン固有の「どの頻度で〈繰り返し〉／いつ〈開始想定〉／どれだけ〈見積〉」が続く。**バンドルだけはこの流れの外**で、下表のとおり「ルーチンから見たバンドル」の確認用の列なので、有効トグルの手前に置く。

| 列 | 仕様 | 要求 |
|---|---|---|
| 名前 | テキスト。**モード色を名前の文字色に反映する**（S-01 と同じ表現。モード未設定は既定の文字色） | F-302 |
| プロジェクト | プロジェクト名を表示。未設定の表記は[共通](./00_共通.md) §2.4 | F-402 |
| モード | モード名を表示。未設定の表記は[共通](./00_共通.md) §2.4 | F-401 |
| 繰り返し | 人間可読の要約表示: 「毎日」「週次(月・水・金)」「隔週(火)」「3週ごと(月)」「月次(25日)」「3日ごと」。週次は week_interval に応じて 1=「週次」・2=「隔週」・n=「n週ごと」と接頭を変える。**曜日がプリセットとちょうど一致するときは曜日の列挙をプリセット名に置き換える**——月〜金がちょうど全選択なら「平日」、土日がちょうど全選択なら「土日」（例: 「週次(平日)」「隔週(平日)」「週次(土日)」）。**ちょうど一致するときだけ**で、余分な曜日を含む場合（例: 月火水木金土）は従来どおり列挙する。**全曜日（月〜日）かつ週間隔1のルーチンは保存時に「毎日」へ正規化される**ため、一覧にも「毎日」と出る（データモデル定義書 §3.4）。週間隔が2以上の全曜日は正規化されないので従来どおり列挙する（例: 「隔週(月・火・水・木・金・土・日)」）。end_date設定時は「〜2026-09-30」を付記 | F-301 |
| 開始想定時刻 | `HH:MM`。時刻が属するセクション名を括弧で併記（導出表示） | F-302 |
| 見積もり | `H:MM` | F-302 |
| バンドル | バンドル色の小さな四角＋バンドル名。**収まらない名前は切り詰める**（折り返すと行高が揃わない）。**分類の他の列より幅を広く取る**——値のほかに色見本を抱えるぶん、同じ字数でも先に溢れる。未設定の表記は[共通](./00_共通.md) §2.4。**アーカイブ済みバンドルも名前をそのまま表示する**（参照を保つ。モード・プロジェクトと同じ扱い）。**この列は「ルーチンから見たバンドル」の確認用**で、束ね方を編集する場は [05_バンドル管理](./05_バンドル管理.md) | F-119 |
| 有効トグル | チェックで `is_active` を即時切替。無効ルーチンは行をグレーアウト。**操作列の左**（値の列をすべて読んだ先）に置く | F-303 |

- **既定の並び順**は開始想定時刻の昇順（同時刻は名前の自然順）＝展開後のデイリーリストと同じ並び。手動の並び替え（ドラッグ等）は提供しない。フィルタ・検索は設けない（ルーチン数は数十件想定）

### 3.1 並べ替え（F-306）

見直しの観点（誰の仕事か・どの分類か・どの頻度か）ごとに一覧を並べ替えられるようにする。

| 項目 | 仕様 |
|---|---|
| 操作 | **列見出しのクリック**。同じ見出しをもう一度押すと降順に切り替わる（昇順 ⇄ 降順のトグル）。追加のUI部品は置かない（N-05） |
| 並べ替えできる列 | 名前 / プロジェクト / モード / 繰り返し / 開始想定 / バンドル。**見積は対象外**（見出しを押しても反応しない） |
| 既定 | 開始想定の昇順。**選んだ並び順は記憶しない**（画面を開き直すと既定に戻る） |
| 同値のときの順序 | どの軸でも第2キーは**名前の自然順**（安定して同じ並びになるようにする） |
| 未設定の扱い | プロジェクト・モード・バンドルが未設定の行は、昇順・降順のいずれでも**末尾**に置く |
| 繰り返しの順序 | 毎日 → 週次 → 月次 → n日ごと（頻度の高い順） |
| 現在の軸の表示 | 並べ替え中の列見出しに昇順/降順の印を付ける |
| 処理の場所 | クライアント側で並べ替える（一覧は全件を保持しており、再取得は不要） |

## 4. 編集フォーム（新規/編集共通）

モーダルまたはインライン展開フォーム。**項目は一覧の列順（§3）に沿って並べる**——同じ画面で同じ順に読めるようにする。開始日・終了日は列を持たないが繰り返しの期間なので、繰り返しの入力群に続けて置く。

| 項目 | 入力仕様 | 必須 |
|---|---|---|
| 名前 | テキスト。**文字数の上限は設けない**（マスタの名前と同じ扱い。[03_マスタ管理](./03_マスタ管理.md) §4「名前の入力」）——生成タスクのタスク名になるため、タスク名（画面定義書01 §8）と揃える | ○ |
| プロジェクト / モード | 各マスタからのセレクト。未設定可（未設定に戻す選択肢の語は[共通](./00_共通.md) §2.4） | |
| 繰り返し種別 | ラジオ: 毎日 / 週次 / 月次 / n日ごと | ○ |
| 曜日 | 週次のみ表示。曜日チェックボックス（複数可、1つ以上必須）。**チェックボックスの上に「平日」「土日」のプリセットボタンを置く**——押すと該当曜日だけが選択された状態になる（月〜金 / 土日）。押したあとに個別のチェックで微調整できる。**繰り返し種別を増やすのではなく `weekdays` ビットマスクへの入力補助**であり、データ構造・展開ロジックは変えない（データモデル定義書 §3.4）。**7曜日すべてを選んで保存すると「毎日」として保存される**（週間隔1のとき。データモデル定義書 §3.4）——入力中に種別を切り替えることはせず、保存後に編集フォームを開き直すと繰り返し種別が「毎日」になっている | 週次時○ |
| 週間隔 | 週次のみ表示。**1〜53の整数**（1=毎週・2=隔週…。上限は1年が触れうる最大週数）。既定1。起算は開始日を含む週（月曜始まり）＝第0週（データモデル定義書 §4.1） | 週次時○ |
| 日 | 月次のみ表示。1〜31（月末超過は月末に丸める旨を注記） | 月次時○ |
| 間隔 | n日ごとのみ表示。正整数 | interval時○ |
| 開始日 | date。既定=今日。intervalの起算日を兼ねる | ○ |
| 終了日 | date。省略可（無期限） | |
| 開始想定時刻 | `HH:MM`。展開順とセクション配置の導出に使う | ○ |
| 見積もり | 分整数 | ○ |
| バンドル | セレクト。未設定可。**アーカイブ済みバンドルは候補に出さない**（モード・プロジェクトと同じ扱い。[03](./03_マスタ管理.md) §4）。**すでに別のバンドルに属していても、ここでは付け替えられる**——[05](./05_バンドル管理.md) O-5 が候補を未所属に絞るのは「バンドルから見ると相手が黙って抜ける」ためで、ルーチン1件の所属を決めているこの場では当のルーチンが対象だと分かっている | |

## 5. 操作仕様

| # | 操作 | 仕様 | 要求 |
|---|---|---|---|
| O-1 | 新規作成 | フォーム入力→保存。対象日（当日以降）を次に表示した時点で展開に反映される（データモデル定義書 §4.1）。開始日の既定は今日のため、当日のリストを開き直せば当日分も展開される。**今日からの展開が不要な場合は開始日を翌日に設定する** | F-301 |
| O-2 | 編集 | 保存後、未展開の日から反映。**展開済みタスクは変更されない**（要件定義書 §5.3） | F-302 |
| O-3 | 有効/無効 | 即時切替。無効化以後は展開されない。既存タスクは残る | F-303 |
| O-4 | 削除 | 確認ダイアログのうえ物理削除。展開済みタスクは `routine_id` を NULL にして残す（ログ保全） | F-303 |
| O-5 | タスクからのルーチン化 | **本画面ではなく S-01 の行メニューから作成する**（画面定義書01 O-12 / §4.1）。作成後の編集・無効化・削除は本画面の O-2〜O-4 と同じ | F-305 |

- **その日だけ展開させたくない場合**は、S-01 で展開されたタスクを削除する。その日はスキップとして記録され再展開されない（F-301 / 画面定義書01 O-8）。ルーチン自体を無効化する必要はない。**特定日だけ内容を変える仕組みは持たない**——その日の見積もりや時刻を変えたいときは、展開されたタスクを S-01 で直接編集する
- 見積もりは1分以上を必須とする（0分は登録できない）
