# データモデル定義書 決定ログ

データ構造・主要ロジックの「なぜそうしたか」を日付順に残す。仕様そのものは[データモデル定義書](./14_データモデル定義書.md)が正。

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-07-22 | 日界（F-116）を専用の設定テーブルではなく `sections.is_day_start`（有効セクション内でちょうど1件）で表す | 日界は「どのセクションが1日の開始か」の1点であり、設定操作も「セクションを選ぶ」形（画面定義書03 §3.1）。1値のために新テーブル＋リポジトリ＋ポート＋ユースケースを増やすより、既にアプリ層の不変条件（有効最低1件・start_time 重複禁止）を持つ sections にフラグを足す方が構成が小さく、オーナーの捉え方とも一致する。有効内の重複は部分ユニーク索引、最低1件はアプリ層、日界セクションのアーカイブ禁止で担保する |
| 2026-07-25 | weekly に `week_interval`（n週おき。NULL/1=毎週）を追加し、隔週などを表現できるようにした（FB-44 / F-301） | 曜日を持つ weekly と n日ごとの interval の隙間（「特定曜日を n週間隔で」）を埋める。新 recurrence_type を足すと weekly と機能重複するため weekly を拡張。起算は start_date を含む週を第0週とし月曜始まり（datepicker と週の起点を揃える）。既存 weekly 行は NULL=毎週で無変更、次回保存時に 1 が入る |
| 2026-07-25 | `week_interval` の値域を 1〜53 に定め、CHECK を `BETWEEN 1 AND 53` にした（FB-44） | weekly は本質的にサブ年のリズムを表す道具で、意味のある最大間隔は「約年1回」。1年が触れうる最大週数=53を上限とし、それ以上（数年に一度）は weekly では表さない。上限は誤入力（530 等）の防御も兼ねる。0003 適用後の追い CHECK 変更のため migration を分けた（0004） |
