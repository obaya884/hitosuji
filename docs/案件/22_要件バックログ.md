未実装要求を**決定状態（レーン）＋熟度タグ＋着手トリガ**で管理する。フェーズ（リリース波）は MVP 完了で役割を終えたため用いない。挙動レベルの仕様判断が発生したら**先に**要件定義書群へ反映し、本書はチェックと一行の要約に留める。**個別FBの内容・反映先はFB管理簿、判断の経緯は各定義書の決定ログ、実装の変遷は git が正**。

- **熟度タグ**: `[仕様済]`＝仕様が固まっている／`[設計済]`＝検討ドキュメントあり／`[列済]`＝データ列は用意済み／`[未詰め]`＝着手時に詳細化。決定状態とは直交する軸。
- **見送りの出口**: 候補を見極めた結果やらないと決めたら、要求定義書 §8 スコープ外＋§10 決定ログへ落とす（F-109・F-207 と同じ扱い）。

## 現況

MVP（Phase 1）完了、2026-07-20 実運用開始。以後は継続運用モードで、案件は運用の気づきから随時流入する。未着手の要求は下記3レーンで管理し、着手条件（トリガ）が来たものから取りかかる。実運用そのものは区切りのない継続活動のため、気づきは随時[FB管理簿](./21_ユーザーフィードバック.md)へ起票する。

# これからの計画

## 確定・着手待ち

やると決めた要求。仕様が固まっているか着手時展開で足りる。作業枠が空き次第着手する。

- [ ] **F-121 現在セクションの見出し強調** `[仕様済]` — 現在時刻が属するセクションの見出し行だけ背景を `band-now`（新設トークン）にする。当日のみ・未分類とアーカイブ済みは対象外。トリガ: 着手枠が空き次第（FB-52 で仕様確定済み）。要件 §5.1 / 画面定義書01 §3.2
- [ ] **F-212 完了タスクを未実行へ戻す** `[仕様済]` — 完了→未実行（打刻を両方クリア）＋戻しの取り消し（Undoトースト）。操作は `U`（完了を選択中）で、取り消しの保留は削除と共通1スロット。トリガ: 着手枠が空き次第（FB-41 で仕様確定済み）。要件 §5.2 / 画面定義書01 O-15 / データモデル定義書 §4.7
- [ ] **F-120 未実行タスクの予想開始時刻** `[仕様済]` — 終了予定（F-104）と同じ積み上げの途中経過を実施時間列へ弱色併記。未実行行のみ・当日のみ。トリガ: 着手枠が空き次第（FB-47 で仕様確定済み）。要件 §5.1 / 画面定義書01 §3.3 / データモデル定義書 §4.3
- [ ] **F-118 その日注力したいタスクのハイライト表示** `[UI未詰め]` — 複数可。モード色（F-401）・消化進捗（F-114）とは独立した「今日ここに注力する」印。データ表現・UI は着手時にデータモデル定義書・画面定義書01 へ展開。トリガ: 着手枠が空き次第（Should ゆえ下記候補より優先）。要件 §5.1 / 要求 §6.1

## 候補・見極め中

運用で必要性・実施可否を判断中。**判断は覆りうる**。見極めた結果やると決めたら「確定・着手待ち」へ、やらないと決めたら見送り（要求定義書 §8・§10）へ動かす。

- [ ] **F-108 タスク名の入力補完と属性流用** `[仕様済]` — 過去タスク名を候補表示し、選択で見積もり・モード・プロジェクト・セクションを引き継ぐ。トリガ: 同種タスクの再入力が手間に感じられたら。画面定義書01 §O-10
- [ ] **F-119 関連ルーチンのバンドル** `[設計済]` — デイリー上で1つの流れ（左ガターの縦線）として視覚化し、束ねの最中の割り込みを検知。要件・データモデル・画面への展開は実装時。トリガ: ルーチン群の連続実行で割り込み見落としが問題化したら。設計は[31_バンドル検討.md](../検討/31_バンドル検討.md)が正。要件 §5.3 / 要求 §6.1
- [ ] **F-206 タスクへの一言コメント** `[列済]` — `comment` 列は用意済み・UI のみ未実装。トリガ: ログに文脈を残したい場面が増えたら（F-501 のコメント列表示もこれが前提）。要件 §5.2 / 画面定義書01 表示要素・04 ログ列
- [ ] **F-304（個別変更のみ）特定日のルーチン展開を個別に変更** `[未詰め]` — スキップは実装済み（MVP）。個別に見積もり・時刻を変える機能。トリガ: 展開済みタスクの直接編集で足りない事例が出たら。要件 §5.3
- [ ] **F-404 モード/プロジェクトによる絞り込み表示** `[未詰め]` — トリガ: タスク数増でリストが見通しにくくなったら。要件 §5.4
- [ ] **F-504 タスクログの CSV エクスポート** — 期間指定でダウンロード。トリガ: 外部での分析・保管の必要が出たら。要件 §5.5
- [ ] **F-505 見積もり精度（見積もり vs 実績）の分析** `[未詰め]` — トリガ: ログ蓄積後、見積もりのクセを可視化したくなったら。`postponed_count` は将来のため記録継続。要件 §5.5
- [ ] **F-506 S-04 レビューの週・月の期間集計** `[仕様済]` — 集計ロジックは日次（F-503）と共通で対象期間を広げる。トリガ: 日次の振り返りが定着し週月の俯瞰が要るとき。要件 §5.5 / 画面定義書04
- [ ] **N-09 スマートフォン対応** — レスポンシブの崩れ防止のみで可。トリガ: 外出先での閲覧・操作が実際に発生したら。必須ではない。要件 §6
