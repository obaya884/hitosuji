# ユーザーフィードバック管理簿

- 作成日: 2026-07-20
- 目的: 実運用で得たオーナーの気づきを一元管理し、今後の開発の入力にする

## 運用ルール

1. 気づきはまず本書に**起票**する（粒度はバラバラで良い。会話で出たものは AI が転記する）
2. 起票時に**分類**する: `不具合` / `改善（軽微）` / `改善（要仕様整理）` / `要求（優先度変更含む）` / `開発環境`
3. 対応するときは通常の開発ルールに従う — **挙動レベルの変更は該当仕様書を先に更新**し（[guide_21_ユーザーフィードバック.md](./guide_21_ユーザーフィードバック.md)）、本書には対応結果と参照先だけを残す
4. 状態は `未対応` / `対応中` / `対応済み` / `見送り` の4つ。対応済み・見送りには日付と理由（または反映先）を書く
5. **対応済み・見送りになったエントリは、状態更新と同じコミットで[closed_21_ユーザーフィードバック.md](./closed_21_ユーザーフィードバック.md)へ移す**（本書には未対応・対応中だけを残す）
