## F-211 終了打刻後の選択送り（2026-08-01）

- レーン: 確定・着手待ち → 完了。トリガ「着手枠が空き次第」（本体は 2026-07-24 に実装済みで、失敗経路のみ残っていた）
- 対応: 終了打刻の選択送りを楽観的更新のロールバック対象に含める。`punch()` が `setSelectedId` を `run()` の外へ同期で置いていたため、サーバが拒むと行だけ実行中へ巻き戻り選択は次のタスクへ進んだままだった。送り先を決めて即座に選択を送るのは変えず（体感0ms）、`finishTaskAction` の結果が失敗なら送る前の選択へ戻す
- 反映先: 画面定義書01 §5（2026-07-27 に条項化済み。今回は実装の追随のみで docs の変更なし）／要件 N-01。実装は `daily-board.tsx` から切り出した `finish()`。回帰テストは `daily-board.test.tsx` に5本（失敗時のロールバック・第3の行を選んでいた場合・`Enter` 経路・確定待ちの選び直し・成功時に送り先へ残ること）を追加した
- 補足: §5 の「元の行」は**打刻した行**とした（行が実行中へ巻き戻る先と揃える）。打刻ボタンは `onSelect` → `onPunch` の順に呼ぶため、別の行を選んだまま ■ を押すと「打刻前の選択」は第3の行になり、そこへ戻すと選択だけ離れた場所へ飛ぶ。ロールバックは**送った選択がそのままのときだけ**行い（`setSelectedId` の関数形更新で現在値と送り先を照合）、確定を待つ間にユーザーが選び直していたらその操作を優先する。送り先が無い（`next === null`）ときは選択を送っていないので、この照合により自動的に no-op になる（専用分岐を持たせない。FB-78 と同じ流儀）
