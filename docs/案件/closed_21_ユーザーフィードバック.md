## 詳細

新書式で移したエントリの詳細節をここに積む（並び順は一覧と同じ）。

### FB-60

- 現象: ボタンにフォーカスがある状態では `Enter` を押しても打刻されない。意図的な除外だが、条項のどこにも書かれていない
- 原因: 実装は `target.tagName === "BUTTON"` のとき打刻しない（打刻ボタンをクリックした直後に `Enter` が二重発火するのを防ぐため。根拠はコードコメントだけ）。[共通](../仕様/13_画面定義書/00_共通.md) §3 の除外規則は「テキスト入力中」までしか書かず、[画面定義書01](../仕様/13_画面定義書/01_デイリーリスト.md) §6 の一覧からも読み取れない
- 対応方針: **挙動は妥当で変更不要**。docs 側に1行足すだけで閉じる
- 発見: T-39 第2バッチ①のテスト作成時（テストは現実装を条項として固定済み）
- 関連: [FB-61](#fb-61)・[FB-65](#fb-65) と同じく「実装は正しく docs の条項が足りない」型なので、**3件まとめて1回の docs 改訂で閉じられる**

### FB-61

- 現象: `?` の説明が文書間で食い違う。画面定義書01 §6 の表は「ショートカット一覧の**表示**」、画面に出る文言（`shortcut-help.tsx`）と実装は「表示・**非表示**」のトグル
- 対応方針: 実装と画面文言が一致しているので、§6 の表記をトグルに寄せれば閉じる
- 発見: T-39 第2バッチ①
- 関連: [FB-60](#fb-60)・[FB-65](#fb-65) とまとめて処理可（同じ「実装は正しく docs が足りない」型）

### FB-65

- 現象: 「元に戻す」の有効期限が明文化されていない。実装では undo トーストを × で閉じるか5秒で自動消去されると保留（`pendingUndo`）も破棄され、以後 `U` を押しても取り消せない＝**トーストの寿命がそのまま取り消せる期限**。[画面定義書01](../仕様/13_画面定義書/01_デイリーリスト.md) O-8 / O-13 は「トーストのボタン、または続けての `U`」としか書かず期限が読み取れない
- 対応方針: 実装の挙動としては妥当（保留を無期限に持つと何を戻すのか曖昧になる）なので、**docs 側に1行足すだけで閉じる見込み**。[共通](../仕様/13_画面定義書/00_共通.md) §2.2 が undo トーストを5秒と定めているので、そこと結ぶ形が自然
- 発見: T-39 第2バッチ③（テストは現実装を固定済み）
- 関連: [FB-60](#fb-60)・[FB-61](#fb-61) とまとめて処理可

### FB-66

- 現象: [共通](../仕様/13_画面定義書/00_共通.md) §2.3「保存中は同じ行の他のセルは編集できない」がデイリーに存在しない。マスタ管理の各テーブルは `isPending` でセルを止めるが、`daily-board.tsx` の `editing` は「いまどのセルを編集しているか」だけを持ち保存中フラグが無いため、**保存の完了を待たずに同じ行の別セルを開ける**
- 原因: デイリーは楽観的更新（N-01）で即座に画面へ反映するため、マスタ（保存完了を待って反映）とは前提が違い、§2.3 をそのまま当てるのが正しいかも自明でない
- 詰める点: ①§2.3 が楽観的更新の画面にも及ぶのか（及ぶなら保存中フラグの導入が要る／及ばないなら §2.3 に適用範囲を書く）②同時編集で実際に壊れる組み合わせがあるか（例: 見積もりを保存中に開始時刻を編集）
- 発見: T-39 第2バッチ②③
- 関連: [FB-63](#fb-63) と同じ条項の話なので**一緒に決めるのが早い**
