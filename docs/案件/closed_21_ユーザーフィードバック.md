## 詳細

新書式で移したエントリの詳細節をここに積む（並び順は一覧と同じ）。

### FB-60

- 現象: ボタンにフォーカスがある状態では `Enter` を押しても打刻されない。意図的な除外だが、条項のどこにも書かれていない
- 原因: 実装は `target.tagName === "BUTTON"` のとき打刻しない（打刻ボタンをクリックした直後に `Enter` が二重発火するのを防ぐため。根拠はコードコメントだけ）。[共通](../仕様/13_画面定義書/00_共通.md) §3 の除外規則は「テキスト入力中」までしか書かず、[画面定義書01](../仕様/13_画面定義書/01_デイリーリスト.md) §6 の一覧からも読み取れない
- 対応方針: **挙動は妥当で変更不要**。docs 側に1行足すだけで閉じる
- 発見: T-39 第2バッチ①のテスト作成時（テストは現実装を条項として固定済み）
- 関連: [FB-61](#fb-61)・[FB-65](#fb-65) と同じく「実装は正しく docs の条項が足りない」型なので、**3件まとめて1回の docs 改訂で閉じられる**

### FB-61

- 現象: `?` の説明が文書間で食い違う。画面定義書01 §6 の表は「ショートカット一覧の**表示**」、画面に出る文言（`shortcut-help.tsx`）と実装は「表示・**非表示**」のトグル
- 対応方針: 実装と画面文言が一致しているので、§6 の表記をトグルに寄せれば閉じる
- 発見: T-39 第2バッチ①

### FB-93

- 現象: [共通](../仕様/13_画面定義書/00_共通.md) §2.4 は「時間の値（見積もり・実績・打刻時刻）の未設定・未確定は**薄色の** `--:--`」と定めているが、実装は画面と列でばらついている — ①**デイリーの未実行行は実績列を空欄**にする（時刻列には予想開始時刻 F-120 が弱色で入る）②**レビューは実行中行の終了時刻・実績を `--:--`** にする ③その `--:--` に**薄色が付くのは見積もり列だけ**で、開始–終了列と実績列は通常色。つまり同じ「時間の値が無い」が、画面によって空欄と `--:--` に、列によって薄色と通常色に割れている
- 原因: §2.4 の「時間の値」の行は FB-55（[完了記録](./closed_21_ユーザーフィードバック.md)）で**見積もり列を念頭に**書かれたもので、実績・打刻時刻まで列挙しているものの各画面の条項（[01](../仕様/13_画面定義書/01_デイリーリスト.md) §3.3「実績は完了時に出す」・[04](../仕様/13_画面定義書/04_レビュー.md) §3.3「実行中の行は終了時刻と実績を `--:--`」）と突き合わせられていない。薄色の指定も見積もり列にしか実装が追随していない
- 詰める点: ①**§2.4 を列ごとに分ける**（見積もりは常に `--:--`、実績・打刻時刻は状態次第で空欄を許す）か、**実装を §2.4 に寄せる**（デイリーの未実行行にも `--:--` を出す）か ②薄色を全列に適用するか、「`--:--` は桁の形で不在を示す記号なので色は要らない」として薄色は見積もり列限定と決めるか ③デイリーの未実行行の時刻列には**予想開始時刻（F-120）が弱色で入る**ので、そこへ `--:--` を足すと二重表示になる——列の役割から整理する必要がある ④「未設定（0分）」「未確定（実行中）」「そもそも打刻前」の3状態を1つの記号で表してよいか（§2.4 は現状2種として書いている）
- 発見: [FB-57](./closed_21_ユーザーフィードバック.md#fb-57)（未設定を表す**語**の統一）のレビュー。`test-reviewer` がデイリーとレビューで実績列の表記が割れていることを、`code-quality-reviewer` が薄色の非対称を、それぞれ独立に指摘した。**語は揃えたが、記号と色はまだ割れている**
- 関連: [完了記録](./closed_21_ユーザーフィードバック.md) FB-57（§2.4 の語を統一。語彙は `src/app/_lib/unset.ts` に集約済みなので、記号・色を変えるときも1か所で済む）・FB-55（§2.4 を新設した側）
